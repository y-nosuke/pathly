# 0027. データの書き出しは DB の写しを zip にし、読み込みは再起動して全部を入れ替える

- Status: Accepted
- Date: 2026-09-27

関連: 仕様は [../specs/backup.md](../specs/backup.md)。

## Context（背景）

- クラウド同期（Phase 3）が無く、記録は端末の中にしか無い。端末の自動バックアップ（[ADR-0016](0016-allow-device-backup.md)）は
  Google 任せで、いつ・何が上がっているか本人には分からない。
- リリース鍵へ切り替えたあと、リリース版は debuggable でなくなり、adb から退避する手段も無くなった
  （[ADR-0026](0026-release-versioning-and-signing.md)）。**端末が壊れたら記録が消える**状態だった。
- 開発版（`com.pathly.debug`）に実データの写しを入れて試したい、という要望もあった。

## Decision（決定）

- **形式**: zip に `manifest.json`（版・DB のバージョン・日時）、`pathly.db`（Room の DB の写し）、
  `settings.json`（SharedPreferences を型つきで）の 3 つを入れる。DB の写しは `VACUUM INTO` で作る
  （記録中でもある時点の一貫した状態になり、WAL の中身も入る）。写しは `journal_mode = DELETE` の単一ファイルにする。
- **読み込みは全部の入れ替え**。足し合わせはしない。
- **差し替えは次の起動の最初に行う**。読み込みを確定したら候補を「予約」として置いてプロセスを終わらせ、
  `PathlyApplication.onCreate` の冒頭（Hilt の注入より前＝誰も DB を開いていないうち）で DB と設定を置き換える。
- 置き換える前の状態をアプリ内に 1 つだけ退避し、「読み込む前の状態に戻す」で戻せるようにする。
- 記録中は読み込ませない。今のアプリより新しい DB のバージョンのファイルは拒否する（下げるマイグレーションは無い）。
- 保存先は SAF（ファイル選択）で本人に選ばせる。ストレージ権限は取らない。

## Alternatives（検討した没案）

- **JSON / GPX など人が読める形式** … 他のアプリでも開けるが、表ごとの変換と、スキーマが変わるたびの保守が要る。
  DB の写しなら欠けるものが無く、古い版の読み込みも既存のマイグレーションに乗る → **却下**（見せる用途の書き出しは別機能として必要になったら作る）。
- **今のデータに足し合わせる** … 同じ経路・場所の重複の扱い（ID の衝突、施設の UNIQUE）が複雑で、
  「書き出した時点に戻す」という目的に対して過剰 → **却下**。
- **開いたまま DB を閉じて差し替え、画面を作り直す** … DAO・Flow・WorkManager・記録サービスなど、古い DB を
  掴んでいるものを漏れなく作り直す必要があり、漏れると壊れた状態で動き続ける → **却下**。プロセスごと再起動するほうが確実。
- **読み込み前の退避を本人に保存させる（もう一度ファイル選択を出す）** … 手間が増えて省かれがち → アプリ内に自動で 1 つ持つ。

## Consequences（結果・トレードオフ）

- 端末の故障・機種変更に本人が備えられる。開発版に実データの写しを入れられる。
- 書き出したファイルは**暗号化していない**。位置の記録がそのまま入るので、扱いは本人に委ねる（仕様に明記）。
- 読み込むとアプリが再起動する。予約を置いたまま再起動しなかった場合も、次に起動したときに入れ替わる。
- 設定ファイルを増やしたら、書き出しの対象（`DataBackupManager.PREFS_NAMES`）に足す必要がある。
- 退避は直前の 1 回分だけ。2 回続けて読み込むと、最初の状態には戻れない（書き出したファイルからは戻せる）。
