# 0036. 行きたいは立ち寄りの記録で終わらせ、終わった行きたいは別テーブルに履歴として残す（v20）

- Status: Accepted
- Date: 2026-11-14

関連: 行きたいを別テーブルに分けた判断は [0013](0013-separate-place-stop-wishlist-tables.md)、
訪問済みを行きたいから独立させた判断は [0020](0020-visited-independent-from-wishlist.md)。

## Context（背景）

要望は当初「訪れた場所について『また行きたい』か『行って満足』かを区別して記録したい」だった。
[0020](0020-visited-independent-from-wishlist.md) では、これを「訪問済み × 行きたい」の組み合わせで
読めることにしていた（また行きたい＝訪問済みで行きたいのまま、満足＝訪問済みで行きたいを外した）。

しかしこの読み方では、**満足と判断した場所と、何も判断していない場所を区別できない**。
立ち寄りの自動検出で作られた駅やコンビニは、何もしなくても「満足」に見えてしまう。

これを解くために「満足」を記録する入れ物を考えたが、検討の途中で要望が変わった。
**満足したかどうかは記録しなくてよい。欲しいのは、行った後にもう一度「行きたい」に入れ直せること**。
入れ直しが残れば、「何度行っても、そのたびにまた行きたいと思う場所」という新しい情報が得られる。

今の行きたいは場所ごとに 1 行で、行った後もそのまま残る。このため「1 回の行きたい」が終わる区切りが無く、
入れ直しを数えられない。

## Decision（決定）

**行きたいは、入れた後にその場所への立ち寄りが記録されたら終わる。終わった行きたいは、
新しく作る `wishlist_fulfillments` に移して残す。**

- `wishlist` の意味は変えない（行がある＝**いま**行きたい。`placeId` は UNIQUE のまま）。
- `wishlist_fulfillments(id, placeId, priority, wishedAt, fulfilledAt)` を新しく作る。
  1 place に複数行あってよい。`places` に従属し CASCADE。行は作るだけで書き換えない。
- **終わる条件**: その場所への立ち寄りで、到着が `wishlist.createdAt` 以降のものが記録された。
  立ち寄りを書き込む経路（自動検出・再解析・付け替え）はどれも `PlaceRepositoryImpl` を通るので、そこで判定する。
  終わったら、同じトランザクションで wishlist の行を消して履歴に 1 行足す（`fulfilledAt` は立ち寄りの到着時刻）。
- **手動の訪問済みの印では終わらない**。旗を自分で外したときは**履歴に残さない**（行かずにやめた）。
- 履歴は、元の立ち寄りをあとで消しても残す（stop は参照しない）。
- 「行きたいで行った回数」＝履歴の件数。旗の見た目（輪郭にチェック）・一覧のバッジ・並べ替え・詳細に使う。
- 自動検出の場所の自動削除・自動統合では、履歴がある場所を「触られた場所」として扱い、消さない・吸収しない。
- 既存の wishlist の行はそのまま残す（さかのぼって終わらせない）。マイグレーションはテーブルを足すだけ。

「行って満足」は記録しない。[0020](0020-visited-independent-from-wishlist.md) の
「満足＝訪問済みで行きたいを外した」という読み方も、この決定で使わなくなる（行きたいは行けば自動で外れるため）。

## Alternatives（検討した没案）

- **組み合わせで読むだけ（DB を変えない）** … 満足と未判断を区別できない。入れ直しも数えられない → 却下。
- **`satisfied_places` を作り、満足を「行の存在」で持つ** … `visited_places` と同じ形で筋は良いが、
  要望が「満足は記録しなくてよい」に変わった → 却下。
- **`wishlist` に status 列（WANT / SATISFIED）を足す** … 2026-07 の軽量案。満足を記録しないので要らない。
  加えて、`wishlist` に行がある＝行きたい、という前提が崩れ、優先度も SATISFIED では宙に浮く → 却下。
- **`wishlist` 自体を履歴にする**（UNIQUE を外し `fulfilledAt` を足す。いまの行きたい＝`fulfilledAt IS NULL`）
  … テーブルは増えない。ただし UNIQUE を外すためにテーブルを作り直す必要がある。行きたいを読む全部の箇所に
  `fulfilledAt IS NULL` が要り、付け忘れると終わった行きたいが「行きたい」として出てしまう → 却下。
- **行っても行きたいは外さず、手で「行った」を押して終える** … 旗を外すだけでは「行った」と「やめた」を
  区別できないので、別の操作が要る。自動で動くことを優先する方針（CLAUDE.md）にも合わない → 却下。
- **手動の訪問済みの印でも終わらせる** … 印は場所に 1 つきりで、二度目以降の訪問を表せない。
  登録と同時に行きたいと訪問済みを付けると、すぐ終わってしまう → 却下。
- **立ち寄りを消したら履歴も戻す** … 誤検知の掃除で行きたいが復活するのは分かりにくい。
  立ち寄りから履歴への参照も要る。まれなことなので、行ったことは事実として残す → 却下。

## Consequences（結果・トレードオフ）

- 行けば旗が自動で外れるので、行きたいのリストが「これから行く場所」だけになる。
- 入れ直しの回数が残り、「行くたびにまた行きたい場所」で並べられる。
- 行きたいの場所に**通りがかりで止まっただけでも**、立ち寄りとして検出されれば行きたいは終わる。
  その場合は旗を押して入れ直す（履歴には 1 回として残る）。
- 記録の無い訪問では行きたいは終わらず、回数にも入らない。
- 履歴を 1 件ずつ見たり消したりする画面は作らない。誤って増えた回数は直せない。
- 書き出しは DB の写しなので、新しいテーブルも含まれる（[0027](0027-data-export-import.md)）。
  古い書き出しはマイグレーションで読める。
