# 0015. 経路の総移動距離は確定時に焼き込み、一覧では点をロードしない（v11）

- Status: Accepted
- Date: 2026-08-15

関連: 経路一覧の仕様は [../specs/tracks.md](../specs/tracks.md)、補正は [../designs/smoothing.md](../designs/smoothing.md)。
一覧の他の派生値（立ち寄り件数）を集計で出す判断は [0003](0003-track-name-and-favorite.md)。

## Context（背景）

履歴の一覧は、経路ごとに移動距離を出す。当初はこれを**表示のたびに計算**していた。
全経路の全 GPS 点を読み込み、その場で平滑化し直して距離を合計する、という作りである。

記録が増えるほど重くなる。しかも計算が UI スレッドで走っていたため、記録が溜まると
履歴タブが目に見えて詰まった。距離順の並べ替えを足したことで、**並べ替えのたびに全点を舐める**
状況にもなっていた。

立ち寄り件数は集計（`COUNT`）で軽く出せるが（[0003](0003-track-name-and-favorite.md)）、
距離は「補正をかけてから測る」ので集計クエリでは出せない。同じ手は使えない。

## Decision（決定）

**記録を確定した時点で距離を計算し、`gps_tracks.totalDistanceMeters` に焼き込む**（DB v11）。

- 一覧はこの列を読むだけで、**GPS 点を一切ロードしない**。距離順の並べ替えもこの列を見る。
- 一覧の 1 行は「経路＋生点の件数だけを数えた射影」で取る（点数表示はこの集計で賄う）。
- v11 より前の経路は `null` なので、**起動時に一度だけ埋める**（対象が無ければ即終了）。

## Alternatives（検討した没案）

- **表示のたびに計算する（従来）** … 常に最新だが、経路数に比例して重くなる。UI スレッドで
  走っていた点も含め、体験が壊れていた → 却下。
- **距離を集計クエリで出す** … 立ち寄り件数と同じ手だが、距離は補正後の点列で測るので SQL では
  出せない（平滑化が要る）→ 不可能。
- **バックグラウンドで計算してキャッシュする** … 焼き込みと実質同じだが、キャッシュの無効化条件を
  持つぶん複雑。記録の確定が唯一の確定タイミングなので、そこで書けば十分 → 却下。
- **記録中も逐次更新する** … 記録中の距離はライブ表示で別に出しており、一覧には記録中の経路を
  混ぜない（[../specs/tracks.md](../specs/tracks.md)）。確定時の一度きりで足りる → 却下。

## Consequences（結果・トレードオフ）

- 履歴タブが経路数に依存しなくなった。並べ替えも列を見るだけで済む。
- **補正のパラメータを変えても、過去の経路の距離は再計算されない**。焼き込んだ値が残る。
  補正をやり直す導線そのものを持たない（[0012](0012-non-destructive-reanalysis.md)）ので、
  この非対称は設計と整合している。
- 既存データの埋め戻しは起動時の一度きり。失敗しても次の起動で再試行される。
- 距離という派生値を列に持つため、**立ち寄り件数（集計）とは扱いが揃わない**。
  「派生値は集計で出す」という [0003](0003-track-name-and-favorite.md) の原則の例外にあたるが、
  集計で出せない値なので許容する。
