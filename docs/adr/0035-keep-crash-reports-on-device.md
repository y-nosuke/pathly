# 0035. 異常終了の原因は端末の中にだけ残し、設定画面から本人がコピーして渡す

- Status: Accepted
- Date: 2026-11-14

## Context（背景）

アプリが落ちても、スタックトレースは logcat にしか出ず、PC をつないでその場で見ない限り分からない。
GitHub Release で配っているので Google Play の Android vitals も使えない。記録中に GPS が止まる原因（#82）も、
OS に止められたのか落ちたのかが後から分からなかった。

一方で「外にデータを送らない」約束（[specs/security.md](../specs/security.md)）がある。将来 Crashlytics に移る構想（#111）はあるが、
それは送り先と送る中身を決め直す話になる。

## Decision（決定）

- 落ちる瞬間に `Thread.setDefaultUncaughtExceptionHandler` でスタックトレース・日時・版をアプリの内部領域のファイルに書く。
- 次の起動で `ActivityManager.getHistoricalProcessExitReasons`（`ApplicationExitInfo`）を読み、ANR・ネイティブの異常終了・
  OS による停止を同じ一覧に足す。OS による停止（メモリ不足など）は、**前景か前景サービス中だったときだけ**異常とみなす。
- 版は起動時に `setProcessStateSummary` で OS に預け、OS の記録にもそのときの版を付ける。
- 残すのは**新しい順に 5 件・1 件 64KB まで**。期間では消さない。設定画面の「記録を消す」で本人が消せる。
- 設定画面の「異常終了の記録」に並べ、全文をダイアログで見せてコピーできるようにする。送るのは本人の手で（Issue に貼る）。
- 座標の形の数（小数点以下 4 桁以上）は書くときに `<数値>` に置き換える。書き出しにも端末のバックアップにも含めない。

詳細は [specs/crash-reports.md](../specs/crash-reports.md)。

## Alternatives（検討した没案）

- **Firebase Crashlytics などの外部サービス** … 自動で集まり、R8 の名前も戻してくれる → **却下理由**: 外に送らない約束とぶつかる。
  送る中身と同意の取り方を決め直す必要があり、#111 で別に扱う。
- **ACRA などのライブラリで端末内に残す** … 依存が増えるわりに、要るのは例外のハンドラ 1 つと OS の記録の読み出しだけ → **却下理由**: 自前で足りる。
- **最新 1 件だけを上書き** … いちばん単純 → **却下理由**: 続けて落ちると最初の原因が消える。
- **件数と期間（30 日）の両方で消す** … → **却下理由**: たまにしか使わないアプリなので、期間で消すと見る前に消えうる。5 件なら量も小さい。
- **OS による停止をすべて入れる** … → **却下理由**: 裏で休んでいるアプリが OS に片付けられるのは毎日のことで、一覧が埋まって本当の異常が押し出される。
- **専用の画面に分ける** … 設定がすっきりする → **却下理由**: 5 件までなら設定の中で足りる。画面遷移を増やさない。
- **落ちた次の起動でダイアログを出す** … → **却下理由**: 通知で知らせる機能は作らない方針。必要なときに本人が見に行けば足りる。

## Consequences（結果・トレードオフ）

- 原因が端末に残り、Issue に貼ってもらえば調べられる。#82 のような「記録中に止まった」も、OS の理由で切り分けられる。
- 本人が貼らない限り開発側には届かない（気づかない落ち方は拾えない）。
- リリース版のスタックトレースは R8 で読めないので、版ごとの `mapping-vX.Y.Z.txt` で戻す手間が残る（[designs/release.md](../designs/release.md)）。
- 例外のメッセージに座標以外（住所・施設名）が入ると防げない。メッセージにそれらを入れない約束（logging.md）で守る。
