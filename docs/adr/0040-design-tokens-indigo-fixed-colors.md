# 0040. 画面の色・文字・余白・角丸・影を Pathly のトークンに決め、壁紙の色は設定で選べるようにする

- Status: Accepted
- Date: 2026-11-17

関連: UI の 4 層（構成・画面の型・部品・トークン）は [designs/ui-direction.md](../designs/ui-direction.md)、
画面の型は [0038](0038-screen-layouts-four-corners-and-tool-row.md)、マーカーの形と色の役割は [0018](0018-marker-shape-confirmed-vs-pending.md)。

## Context（背景）

画面の型（0038）は決めたが、その下の層のトークン（色・文字・余白・角丸）は決まっていなかった。

- `PathlyAndroidTheme` は既定でダイナミックカラー（壁紙の色）を使っており、`Color.kt` の暖色のスキームは
  ほぼ使われていなかった。画面の色は端末ごとに変わり、地図のマーカー・経路の色との組み合わせを決められない。
- マーカー・経路の色は `RouteMap.kt` などに直書きで散らばっていた。
- 角丸（8・10・12・16・20・24・28dp）と影（2・3・4・8・12dp）が画面ごとにばらばらだった。

画面を 1 つずつ型へ移す Issue（#193〜#197）で新しく作る部品が、最初から同じ値を使えるようにしたい。
後から全画面に手を入れ直さずに済むよう、移す前にトークンを決める。

## Decision（決定）

claude.ai の Design System（[Pathly Design System](https://claude.ai/artifact/T9PLHBYVuDhiRz7wtqHYRd)）で案を並べて選び、
`ui/theme/` のトークンにした。**正はコード**で、Design System と [specs/screens.md](../specs/screens.md) の「デザイントークン」はそれに揃える。

- **色の方向性は「藍」**。主役（`primary`）は落ち着いた青 `#2F5BA8`、地は青みに寄せた白。
  `secondary` は Material 3 の慣習どおり落ち着いた青灰（下のタブの選択中の印・選択中の行・案内の帯など「控えめな選択」）、
  `tertiary` は経路の橙を文字が読める濃さにしたもの。
- **「行った・動いている」の緑は Material 3 の役割に入れず `PathlyStatusColors.visited` に分ける**（明暗で値を持ち、壁紙の色でも変えない）。
  最初は `secondary` を緑にしたが、M3 の部品は `secondaryContainer` を選択の印に使うため、下のタブの印や案内の帯まで緑になった。
  暗いテーマは色相を変えず明るさを入れ替える。Material 3 の役割（surfaceContainer まで）を全部埋める。
- **地図に描くものの色は `PathlyMapColors` にまとめ、テーマに従わせない**（明暗・壁紙の色で変えない）。値は今のまま。
- **ダイナミックカラーは既定で使わず、設定の「見た目 › 壁紙の色を使う」で選べる**ようにする（`pathly_settings` の
  `use_dynamic_color`。書き出しの対象にも入る）。
- **文字**は端末の標準の書体のまま（フォントを同梱しない）、Material 3 の段に合わせ、日本語向けに本文の行の高さを少し広げる。太さは 3 つ。
- **余白**は 4dp の段（`PathlySpacing`）。今の画面の余白の数値は、型へ移す Issue で置き換える。
- **角丸**は中くらいの段: 小 8（チップ・帯）・中 12（カード・案内）・大 20（シートの上端・FAB）・丸（地図の丸ボタン・検索窓・ピル）。
  `MaterialTheme.shapes` と `PathlyShapes` に入れ、今の画面の角丸もこれに置き換えた。
- **影**は地図の上に浮かぶものだけに 3 段（`PathlyElevation`: 2・4・8dp）。今の画面の影もこれに置き換えた。

## Alternatives（検討した没案）

- **色の方向性「森」（深い青緑）** … お出掛け・自然の雰囲気は出るが、地図の公園の緑や、出発・訪問済みの緑のマーカーと近く、
  主役のボタンと地図の上の印が見分けにくい。却下。
- **色の方向性「夕焼け」（今の暖色を落ち着かせて継ぐ）** … 今の印象を残せるが、主役と経路が同じ橙になる。
  経路の色を青に変えると、今のオレンジの経路に慣れた目には違和感が大きく、立ち寄りの帯（濃い青）とも近くなる。却下。
- **ダイナミックカラーを使わない（選べない）** … 決めた色の組み合わせを確実に保てるが、壁紙に合わせたい人の選択肢が消える。
  地図の色をテーマから切り離せば、画面の色が変わっても地図の意味は崩れないので、選べるようにした。
- **ダイナミックカラーを今のまま既定で使う** … 決めたトークンが普段は見えず、Design System と画面が一致しない。却下。
- **角丸を大きめ（12・16・28）／小さめ（4・8・16）** … 大きめはやわらかいが一覧の行やチップが間延びし、小さめは今の画面から離れて
  移すときの差分が大きい。今に近い中くらいにした。
- **フォントを同梱する（Noto Sans JP など）** … 端末ごとの差は減るが APK が数 MB 重くなり、端末の文字設定との相性も確かめる必要がある。
  Android の日本語の標準が Noto Sans CJK なので、同梱しなくても見た目はほぼ同じ。却下。
- **余白も今すべて置き換える** … 数百か所あり、画面を型に移す Issue で組み直す場所と重なる。二度手間になるので、トークンだけ用意して移すときに使う。

## Consequences（結果・トレードオフ）

- 画面の色が端末によらず決まった組み合わせになり、Design System の見本と同じに見える。
- 壁紙の色を使っても地図の色は変わらないので、マーカー・経路の意味は保たれる。代わりに、壁紙の色の画面と地図の色の組み合わせは確かめていない。
- 色・角丸・影を変えるときは、コード・Design System・screens.md の 3 か所を一緒に直す（正はコード）。
- 余白の数値はしばらく画面ごとに直書きのまま残る。#193〜#197 で画面を型に移すときに `PathlySpacing` へ置き換える。
