# 0049. 場所と立ち寄りの Repository は窓口ごと 3 つに分け、ロックと状態は 1 つを共有する

- Status: Accepted
- Date: 2026-11-26

関連: 今の姿は [designs/architecture.md](../designs/architecture.md) の「場所と立ち寄りは 3 つの窓口に分け、ロックと状態は 1 つを共有する」。

## Context（背景）

`PlaceRepository` は場所と立ち寄りの永続化・命名を 1 つの窓口で受け持ち、実装の `PlaceRepositoryImpl` は約 1100 行の 1 クラスだった。
#263 で大きいファイルを分けたときも、これだけは分けずに残した（#266）。

分けにくいのは、1 つの `Mutex`（記録中の検出・保存・命名と、編集を直列にする）と、メモリ上の状態をほぼすべての処理で共有しているため。
状態は、記録中の立ち寄り（`detectionHighWaterMillis`・`liveStopPlaces`・`manualLiveStops`・`currentStop`）と、
取り消しの控え（`lastStopChange`・`lastPlaceMerge`・`lastMergeLiveTracks`）。さらに 1 回の操作が状態をまたぐ。

- 名前解決で同じ施設の既存の場所に自動でまとめると、記録中に覚えている場所を差し替える。
- 場所をまとめると、記録中の場所を差し替え、立ち寄りの取り消しの控えを捨てる（消えた場所を指すことがあるため）。
- 記録中の検出は、場所の確保と名前解決を中で呼ぶ。

呼び出し元（ViewModel・UseCase・Service・Worker）は 30 近いメソッドのうち数個しか使わないのに、全部を持つ窓口に依存していた。

## Decision（決定）

- **窓口（domain のインターフェース）を 3 つに分ける。** 呼び出し元は使うものだけを持つ。
  - `LiveStopRepository` … 記録中の立ち寄り（`currentStop`・`updateStopsForTrack`・`startLiveStop`・立ち寄り中の直し・やめる）。
  - `StopRepository` … 記録された立ち寄り（一覧・再解析・手動追加・付け替え・メモ・期間・まとめる・削除と取り消し）。
  - `PlaceRepository` … 場所（登録済みの場所・近くの場所・場所の確保・名前の取得・同じ施設の確認待ち・まとめると取り消し・名前）。
- **ロックと状態は 1 つを共有する。** data の `PlaceStopSession`（`@Singleton`）が `Mutex` 1 つと状態を持ち、3 つの実装が同じものを受け取る。
- **ロックの中で使う共通の処理は `PlaceOperations` に置く**（場所の確保・名前解決・同じ施設の自動まとめ・行きたいの「行った」・後片付け）。
  `Mutex` は再入できないので、ロックを持ったまま別の窓口の公開メソッドは呼ばず、`PlaceOperations` を直接呼ぶ。
- 挙動は変えない。

## Alternatives（検討した没案）

- **分けない** … ロックの持ち方は変えずに済む → 1100 行の読みにくさと、呼び出し元が全部を持つ窓口に依存する形が残るので**却下**。
- **実装だけ分けて窓口は 1 つのまま** … 呼び出し元・DI・#262 と重なるファイルに触れずに済む → 呼び出し元から見て何に依存しているかが
  分からないままなので**却下**。
- **ロックを状態ごとに分ける**（記録中・取り消し・場所で別々の `Mutex`） … 部品が独立する → 1 回の操作が複数の状態をまたぐので、
  ロックを順に取る決まりが要り、取り違えるとデッドロックや状態のずれ（まとめた場所を記録中の立ち寄りが指し続ける など）が起きるので**却下**。
- **窓口どうしが互いの公開メソッドを呼ぶ**（共通の処理の部品を置かない） … 部品が 1 つ減る → `Mutex` が再入できないので、
  ロックの中から呼ぶとデッドロックするので**却下**。

## Consequences（結果・トレードオフ）

- 呼び出し元の依存が狭くなり、テストでモックするものも使う窓口だけになる。
- 3 つの実装は `PlaceStopSession` と `PlaceOperations` を通じて結び付いたまま。どの状態をどこで触るかは、ファイルを分けても
  読み合わせる必要がある（状態は必ず `Mutex` の下で触る、という決まりで守る）。
- 窓口が 3 つに増えたので、場所と立ち寄りに新しい操作を足すときは、どの窓口に置くかを決める（記録中のメモリの状態に触るなら
  `LiveStopRepository`、stops の行なら `StopRepository`、places の行なら `PlaceRepository`）。
