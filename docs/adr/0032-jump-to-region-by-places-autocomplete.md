# 0032. 記録画面の「地域へ移動」は、Places の Autocomplete を地域に絞って使い、入口は「検索して登録」と分ける

- Status: Accepted
- Date: 2026-11-12

関連: 費用の考え方は [0014](0014-place-naming-cost-policy.md)、地域の名前を Geocoder で付けるのは [0029](0029-place-region-by-geocoder.md)。仕様は specs/map.md の「地域へ移動」。

## Context（背景）

記録画面の地図で別の街を見たいとき、ピンチとドラッグで動かすしかなかった（#150）。旅行先や行ったことのない地域にも
移れるよう、地名を入れて探し、地図をその地域へ移したい。

決めることは 3 つあった。地名の探し方（有料の Places か、無料の Geocoder か）、移す範囲、
すでにある「検索して登録」（施設を探して登録する、#153）と入口をまとめるかどうか。

## Decision（決定）

- **Places の Autocomplete を、地域の種類（`(regions)`: 国・都道府県・市区町村・郵便番号など）に絞って使う。**
  見た目と動きは「検索して登録」と同じ検索窓（地図に重ねる窓・候補のカード）を共有する。
- **選んだ地域の範囲（viewport）が収まるように地図を移す。** 範囲の取得（Place Details）で引く項目は ID・位置・範囲だけにし、
  打っている間の候補と 1 つのセッションにまとめる。範囲が返らないときだけ、位置のまわりの決まった広さにする。
- 候補は、窓を開いたときに地図に映っていた範囲を優先する（location bias。料金は変わらない）。
- どこがその地名かを示すため、地域の中心に地名つきの目印を出す。地名は候補の文字を使い、Places から名前は引かない。
  境界を描く（Maps SDK の境界のスタイル。マップ ID が要る）のは別に検討する（#157）。
- **入口は「検索して登録」と分ける**（地球のボタンを別に置く）。

## Alternatives（検討した没案）

- **Android の Geocoder（地名 → 座標）** … 無料だが、打っている途中の候補が出ず（1 回ごとに確定の検索になる）、
  範囲も取れないので寄せる縮尺を決め打ちにするしかない。「国」と「町」で同じ縮尺になり、見たい地域が収まらない → 却下。
- **中心に決まった縮尺で寄せる** … 範囲の大きさが地域ごとに違い（国・県・市）、どれかで必ず合わない → 却下。
- **「検索して登録」と同じ検索欄にまとめ、地域を選べば地図を移し、施設を選べば登録へ進む** … ボタンは 1 つで済むが、
  選んだあとの動きが候補の種類で分かれ、「登録するつもりが地図が動いただけ」「移すつもりが場所シートが出た」と迷う。
  候補も施設と地域が混ざって探しにくい。目的（登録する／見る）が違うので、入口で分けたほうが分かりやすい → 却下。

## Consequences（結果・トレードオフ）

- 候補の出方は場所の検索と揃い、同じ名前の市が複数あっても近いほうが上に来る。国から町まで、範囲に合わせて収まる。
- 地域を選ぶたびに Place Details の料金がかかる（候補を打つぶんはセッションにまとまる）。引く項目を絞って安い区分に収め、
  ユーザーが明示的に選んだときだけ叩く（[0014](0014-place-naming-cost-policy.md) の「明示的に押したときは制限の外」と同じ扱い）。
- オフラインでは使えない（候補が出ない）。
- 右上のボタン列が 1 つ増える。
