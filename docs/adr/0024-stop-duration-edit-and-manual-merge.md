# 0024. 同じ場所への複数の立ち寄りは自動でまとめず、期間の編集と手動統合をユーザーに渡す

- Status: Accepted
- Date: 2026-08-29

関連: 非破壊の原則は [0012](0012-non-destructive-reanalysis.md)、付け替えの考え方は
[0007](0007-reassign-stop-this-visit-only.md)、同一性の決め方は [0023](0023-place-identity-and-coordinate-anchor.md)。

## Context（背景）

広い敷地では、**1 回の外出で同じ場所に複数の立ち寄りが付く**。

```text
入口で5分        → 立ち寄り①
   ↓ 300m 歩く
ゾウ舎の前で20分 → 立ち寄り②
   ↓ 200m 歩く
売店で10分       → 立ち寄り③
```

立ち寄りの区切りは 50m のクラスタなので、①②③が別々に検出されるのは正しい。
そのうえで①②が同じ施設に解決されれば、[0023](0023-place-identity-and-coordinate-anchor.md) の
統合によって**同じ place への立ち寄りが 2 件**になる。

これを自動でひとつにまとめるべきか。まとめれば一覧はすっきりするが、「入口とゾウ舎で
別々に過ごした」という事実が消える。まとめなければ、履歴に同じ名前が 2 行並ぶ。
どちらが正しいかは**その日その人の解釈**で決まり、アプリには決められない。

加えて、検出は位置と時間だけで判定するので、区切り方そのものが実態とずれることがある
（信号待ちで切れる・屋内で座標が固まる）。**期間を手で直したい**という要望は前からあった。

## Decision（決定）

**アプリは自動でまとめない。ユーザーが「滞在期間の編集」と「立ち寄りの統合」で決める。**

- **滞在期間の編集** … `stops` の到着・出発を直接編集する。**GPS 点・補正後の点は一切触らない**
  （観測した事実は変えない → [0012](0012-non-destructive-reanalysis.md)）。
- **立ち寄りの統合** … 選んだ複数の立ち寄りを 1 件にする。到着は**最も早い到着**、出発は
  **最も遅い出発**、訪問メモは連結する。
- **立ち寄り期間の重なりは禁止しない**（完全に含む「入れ子」も含む）。統合しても、**間に挟まって
  いた別の場所の立ち寄りは消さない**。上の例で①②を統合すると、ゾウ舎はその期間の内側に残る。
- **スキーマは変えない。** `stops` の更新と削除だけで実装できる。取り消しは一括削除で使っている
  スナップショット（`undoLastDeletion`）と同じ形で載せる。

重なりを許すのは、**入れ子が現実に起きる**からである。モールに 3 時間いて、その中のカフェに 30 分。
動物園に 5 時間いて、その中のゾウ舎に 20 分。禁止すると、まさにやりたかった統合ができなくなる。

## Alternatives（検討した没案）

- **同じ place への時間が近い立ち寄りを自動で統合する** … 一覧はすっきりするが、
  「入口とゾウ舎で別々に過ごした」情報が消える。しかも「時間が近い」を決める新しいしきい値
  （何分空いたら別の訪問か）が必要になり、50m/3 分に続くマジックナンバーが増える → 却下。
- **立ち寄り期間の重なりを禁止する** … 検証は単純になるが、建物の中の店・敷地の中の施設という
  現実の入れ子が表せず、統合の主目的も果たせない → 却下。
- **検出のしきい値（50m）を施設の大きさに応じて変える** … 敷地の広さを知る手段がない
  （Places は代表点しか返さない）。当てずっぽうの可変しきい値は再現性を損なう → 却下。
- **期間の編集にあわせて補正後の点も編集する** … 「どこにいたか」の記録が編集で書き換わり、
  距離や軌跡の表示まで動く。事実と解釈を混ぜてはいけない → 却下。

## Consequences（結果・トレードオフ）

- 履歴に**入れ子になった立ち寄り**が並ぶ（「動物園 10:00-15:00」「ゾウ舎 10:30-10:50」）。
  地図の帯も重なって描かれる。**読みにくさは実装して画面を見てから評価する**。仕様で先回りして
  禁止はしない。
- 手で期間を編集した立ち寄りは、**再解析の候補から自然に外れる**。`detectMissingStops` が
  「既存と時間帯が重なる候補」を除外するので、編集後の期間で判定される。「編集済み」フラグの
  列は要らない。
- 検出は事実を出すだけ、解釈はユーザーがする、という [0012](0012-non-destructive-reanalysis.md) の
  姿勢が、削除・再解析・付け替えに続いて期間にも及ぶ。
- 統合は不可逆に見えるが、元の 2 件に戻したければ期間を編集して分け直せる（自動では戻らない）。
  取り消しはスナックバーの時間内だけ。
- CLAUDE.md で Phase 2 以降に送っていた「記録の詳細編集」の一部を先に着手することになる。
