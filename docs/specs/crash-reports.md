# 異常終了の記録の仕様

アプリが落ちたとき・OS に止められたときに、**原因を端末の中に残し、設定画面で見られるようにする**。
不具合の Issue に貼って原因を調べるためのもの。決定の背景と没案は [ADR-0035](../adr/0035-keep-crash-reports-on-device.md)。

> 対応する Issue: #110。将来の Firebase Crashlytics（#111）とは別。

---

## 何を残すか

2 つの出どころを、**1 つの一覧**にまとめる。

| 出どころ                                  | 拾うもの                                             | 中身                                          |
| ----------------------------------------- | ---------------------------------------------------- | --------------------------------------------- |
| アプリ自身（落ちる瞬間に書く）            | 処理されなかった例外で落ちた                         | スタックトレース・日時・版                    |
| OS が覚えている終わり方（次の起動で読む） | 応答なし（ANR）・ネイティブの異常終了・OS による停止 | OS の説明・状態・メモリ。ANR はスレッドの様子 |

OS の終わり方のうち、**一覧に入れるのは「異常」だけ**。

| 種類                                         | 入れるか                                                                                                                                 |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 落ちた（例外）                               | 入れる（アプリ自身が書けなかったときの穴埋め。書けていれば重ねない）                                                                     |
| 落ちた（ネイティブ）                         | 入れる                                                                                                                                   |
| 応答なし（ANR）                              | 入れる                                                                                                                                   |
| 起動に失敗した                               | 入れる                                                                                                                                   |
| 資源の使いすぎで止められた                   | 入れる                                                                                                                                   |
| メモリ不足・その他で OS に止められた         | **画面に出ていたか記録中（前景サービス）だったときだけ**入れる。裏で休んでいるアプリが OS に片付けられるのはいつものことで、異常ではない |
| 自分で終えた・本人が止めた・更新・権限の変更 | 入れない（ふつうの終わり方）                                                                                                             |

- OS の記録は前回読んだところから先だけを見る。同じものを二度入れない。
- 版は、落ちたときに動いていた版を残す（OS の記録には、起動時にアプリが OS に預けた版を使う）。

## どこまで残すか

- **新しい順に 5 件まで**。6 件目が入ると、いちばん古いものを消す。期間では消さない。
- 1 件あたりの中身は **64KB まで**に切り詰める（ANR のスレッドの様子は大きいため）。
- 本人が設定画面の「記録を消す」で全部消せる。
- アプリの内部領域に置き、**外には何も送らない**。データの書き出し（[backup.md](backup.md)）にも端末のバックアップにも含めない
  （その端末の、その版の診断情報なので、持ち出しても意味がない）。

## 混ぜないもの

不具合の Issue（公開）に貼る前提なので、**座標・住所・施設名を中身に入れない**。

- 例外のメッセージにもログと同じ禁止を適用する（→ [../designs/logging.md](../designs/logging.md)）。
- それでも紛れ込んだときのために、**小数点以下が 4 桁以上の数（座標の形）は `<数値>` に置き換えて**残す。
- 端末の機種名と Android の版は入れる（原因の切り分けに要るため）。端末固有の ID は入れない。

## 設定画面での見せ方

「このアプリについて」の下に「異常終了の記録」を置く（→ [screens.md](screens.md#4-設定画面)）。

```text
異常終了の記録
  11/14 09:12  落ちた（例外）                 >
  11/13 18:40  OS に止められた（メモリ不足）   >
  [記録を消す]
```

- 1 件を 1 行（日時・種類）で、新しい順に並べる。無いときは「ありません」。
- 押すと全文のダイアログが出る。種類・日時・版・端末・中身をスクロールして読め、**[コピー]** で全文をクリップボードに入れられる。
- 「記録を消す」は確かめてから全部消す（取り消しは無い）。
- 落ちたことを起動時に知らせたりはしない（通知で知らせる機能は作らない方針）。

## リリース版で読むには

リリース版は R8 で名前が短くなっているので、スタックトレースはそのままでは読めない。
同じ版の `mapping-vX.Y.Z.txt` と `retrace` で元の名前に戻す（→ [../designs/release.md](../designs/release.md#リリース版のエラー情報を読む)）。
