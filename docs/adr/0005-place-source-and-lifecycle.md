# 0005. 場所に由来（source）を持たせ、自動回収は検出由来のみにする（v10）

- Status: Accepted
- Date: 2026-08-08

関連: 現状の設計は [../designs/places-and-stops.md](../designs/places-and-stops.md) の「場所の由来（source）と自動回収」。

## Context（背景）

`places`（場所）は経路から独立した共有エンティティで、立ち寄り（`stops`）・行きたい（`wishlist`）が `placeId` を参照する。
立ち寄り削除時、参照が無くなった place を自動回収（削除）していた。だがこの回収は**由来を問わない**ため、
ユーザーが場所タブで**明示的に登録した場所**（訪問も行きたいも指定せずに登録できる）が、近くの立ち寄りと
座標同定（30m）で相乗りしてしまうと、その立ち寄り削除の巻き添えで**勝手に消える**危険があった。

さらに、後続で「誤検知した立ち寄りを正しい場所に付け替える」機能（この訪問だけ付け替え）を入れると、
元の誤検知 place が毎回孤立するため、回収が安全でないと事故につながる。

## Decision（決定）

- `places` に **`source`（`DETECTED` / `USER`）** を持たせる（**DB v10**・既存行は安全側の `USER` でバックフィル）。
  - `DETECTED` … 自動検出が作った使い捨て。参照ゼロなら自動回収してよい。
  - `USER` … ユーザーが明示的に作った（場所登録・手動立ち寄り追加・キーワード検索）。**自動では消さない**。
- 自動回収（`deleteStops`）は **参照ゼロ かつ `DETECTED`** のときだけ place を消す。`USER` は保持。
- `findOrCreatePlace(lat, lon, source)` は新規作成時に由来を刻む。既存再利用時、`DETECTED` を `USER` へ**昇格**する
  （ユーザーが触った場所を守る。降格はしない）。

## Alternatives（検討した没案）

- **由来を持たず、回収をやめる（一切自動削除しない）** … 誤検知 place がゴミとして溜まる。付け替え機能の後始末が
  できず、場所タブが汚れる → 却下。
- **既存行を `DETECTED` でバックフィル** … 既存のユーザー登録場所まで回収対象になり、まさに防ぎたい事故が起きる →
  却下（`USER` で保護）。
- **`name` や `google_places` の有無で「ユーザーが作ったか」を推測** … 未命名の手動登録や、命名済みの検出などが
  あり誤判定する。明示的な由来列が確実 → 却下。

## Consequences（結果・トレードオフ）

- ユーザーが登録した場所は、参照ゼロでも自動では消えない（明示削除は場所タブから）。誤検知の使い捨てだけ回収される。
- 追加列は既存行で `'USER'`（`NOT NULL DEFAULT 'USER'`・バックフィル用）。エンティティ側に既定を宣言しないため
  Room の起動時検証は DB の DEFAULT を無視する（[0003](0003-track-name-and-favorite.md)・[0004](0004-capture-all-gps-fields-and-batch.md) と同じ扱い）。
- 既存の検出 place（v10 以前に作られたもの）は `USER` 保護になり自動回収されない（保守的・データ消失なし）。以後の
  検出 place だけ `DETECTED` として回収対象になる。

## 今後の方針（この ADR の範囲外・順次対応）

長い設計議論で合意した、場所同定と誤検知修正の全体像（本 ADR では **source と安全な回収のみ**を実装）:

1. **同定を identity 優先に**: `findOrCreatePlace` に任意の `googlePlaceId` を渡し、**ID があれば ID で同定**
   （隣接する別店＝別 place に分離、同一 POI の再訪はまとめる）、無ければ座標フォールバック。POI 由来の place は
   Google 座標で保存。POI タップで既存に当たったら「登録済み」を軽く通知。
2. **ID 無しユーザー操作**: 登録済みの場所を地図（記録・履歴詳細・場所詳細）にマーカー表示（トグル）し、
   **マーカータップで紐付け／空タップで新規**。表示 OFF のときのフォールバックとして「近くに既存あり→紐付け/新規」の
   確認ダイアログを出す。
3. **誤検知の選び直し（Model B）**: 確定済みの立ち寄りを、近くの POI 候補から選び直して**この訪問だけ**正しい place に
   付け替える。余った `DETECTED` の孤立 place は本 ADR の回収で安全に片付く。検出（自動）は座標同定のままで、
   間違いはこの訂正で直す。
