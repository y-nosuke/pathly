# 0020. 訪問済みを行きたいから独立させ、別テーブルに持つ（v14）

- Status: Accepted
- Date: 2026-08-18

関連: 場所・立ち寄り・行きたいをテーブルで分けた判断は [0013](0013-separate-place-stop-wishlist-tables.md)。
ユーザー入力と Google 由来を分ける方針は [0001](0001-place-data-separation.md)。

## Context（背景）

「訪問済み」には 2 つの出どころがある。**立ち寄り（stops）の記録**と、**手動で付ける印**（記録が
残っていない訪問。このアプリを使う前に行った場所など）。

このうち手動の印は v13 まで `wishlist.visitedAt` に置いていた。行きたいリストの中の「もう行った」
というチェックとして始めたためだが、これには 2 つの困りごとがあった。

1. **行きたいに登録しないと訪問済みにできない**。置き場所が wishlist の行しか無いので、
   UI でも訪問済みのトグルを行きたい ON の中に入れ子にするほかなかった。
2. **行きたいを外すと訪問済みも消える**。wishlist の行ごと消えるため、「行って満足したので
   行きたいリストからは外す」という自然な操作で訪問の事実まで失われる。

行きたい（これから行きたい）と訪問済み（もう行った）は本来**別の軸**で、片方が他方の前提には
ならない。

列名 `visitedAt` も誤解を招いていた。入るのは**印を付けた日時**であって、訪れた日時ではない。

## Decision（決定）

**`visited_places` を新設し、手動の「訪問済み」はそこに持つ。**

- `visited_places(id, placeId UNIQUE, markedAt)`。**行の存在＝訪問済み**で、付ける＝挿入・
  外す＝削除しかしない（行を書き換えない）。
- `markedAt` は**印を付けた日時**。名前でそう分かるようにした。実際に訪れた日時を知りたいときは
  stops の到着時刻を見る。
- `wishlist.visitedAt` は**廃止**。wishlist は優先度だけを持つ。
- 判定は今までどおり `立ち寄り記録がある or 手動の印がある`。UI では、立ち寄り記録がある場所は
  件数を出すだけで手動の切り替えを見せない（記録の方が確かなので、印で上書きさせない）。
- フォームでは**訪問済みを行きたいの入れ子から出す**。登録フォームにも置き、
  「前に行ったことがある場所」を登録と同時に訪問済みにできる。

### なぜ places の列にしないか

`places` は**静的に保つ**（→ [0013](0013-separate-place-stop-wishlist-tables.md)）。場所そのものは
名前と座標で、行きたい・立ち寄り・訪問済みのような**移ろう状態は別のテーブルに置く**という
分け方をここでも踏襲する。メモ（`places.note`）は場所の説明で状態ではないので places に置いている。

## Alternatives（検討した没案）

- **`places.visitedAt` を足す** … 結合が増えず一番簡単。だが places が状態を持ち始め、
  [0013](0013-separate-place-stop-wishlist-tables.md) の分け方が崩れる。行きたいだけ別テーブルで
  訪問済みは列、という不揃いも残る → 却下。
- **`wishlist` に残したまま、訪問済みにするとき自動で行きたい行を作る** … テーブルは増えないが、
  行きたくない場所まで行きたいリストに並ぶ。「行きたい」の意味が壊れる → 却下。
- **`wishlist` に status 列（WANT / SATISFIED）を持たせる** … 以前検討した案。1 列で「また行きたい」
  と「満足」を表せるが、結局 wishlist に居ることが前提で、行きたいに入れていない場所を
  訪問済みにできない。今回の困りごとが解けない → 却下。
- **列名を `markedVisitedAt` のまま wishlist に置き、名前だけ直す** … 誤解は減るが、
  独立させたいという本題に手が付かない → 却下。
- **`visited_places` に `updatedAt` も持たせる** … 他のテーブルと形は揃うが、この行は作るか消すかで
  更新しないので常に `markedAt` と同じ値になる。無い方が「書き換えない」ことが伝わる → 却下。

## Consequences（結果・トレードオフ）

- **行きたいと訪問済みを別々に選べる**。行きたいを外しても訪問の事実は残る。
- 登録と同時に訪問済みにできるので、過去に行った場所をまとめて登録できる。
- 読み取りに**結合が 1 つ増える**（`places → visited_places`）。1 place につき最大 1 行なので実害は小さい。
- 場所を消すと印も CASCADE で消える。削除の取り消し（Undo）では印も一緒に復元する。
- 同じ場所に二度印を付けても**最初に付けた日時が残る**（挿入は IGNORE）。付け直したことは追えない。
- 「また行きたい（訪問済みだが行きたいのまま）」と「満足（訪問済みで行きたいを外した）」は、
  2 つの軸の組み合わせで表せるようになった。専用の状態は持たない。
