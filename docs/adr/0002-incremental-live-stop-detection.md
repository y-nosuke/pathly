# 0002. 記録中の立ち寄り検出を境界以降のインクリメンタルにする（削除の復活防止）

- Status: Accepted
- Date: 2026-08-07

関連: 現状の設計は [../designs/places-and-stops.md](../designs/places-and-stops.md) の「保存・命名のトリガー → 記録中（自動・ライブ）」。

## Context（背景）

記録中は GPS 更新のたびに `updateStopsForTrack` が走り、`StopDetector.detect` の結果を保存する。
旧実装は「保存済み立ち寄り**件数**（`StopDao.countByTrack`）より検出数が多ければ末尾を追記する」という
**件数基準の差分保存**だった。これに 2 つの問題があった:

1. **削除した立ち寄りが復活する**。ユーザーが記録中に立ち寄りを削除すると件数が 1 減る。GPS は変わらないので
   検出結果は同じ（滞在の痕跡が残る）。次の更新で「末尾が 1 件足りない」と誤判定し、末尾の検出を**再挿入**して
   しまう（中間削除なら末尾の重複、末尾削除ならその 1 件がそのまま復活）。
2. **毎ティック全経路を再計算する**。`detect` に毎回**全補正点**を渡すため、過去に確定済みの立ち寄り区間まで
   毎回スキャンし直す。長時間の外出ほど無駄が増える（セッション通算で概ね O(n²)）。

## Decision（決定）

記録中の検出を**境界以降だけのインクリメンタル**にする。

- **境界** = 「最後に確定した立ち寄りの `departureTime`」（ミリ秒）。
- 毎ティック、境界より**後の補正点だけ**を `StopDetector` にかける（`SmoothedPointDao.getByTrackAfter`）。
  貪欲スキャンは境界より手前の点に依存しないため、末尾のクラスタ分割は全点検出と**等価**。
- 境界はトラック単位で**メモリに保持**し、セッション中は**単調増加**（**削除では下げない**）。未設定時
  （プロセス再起動後の再開）だけ、保存済み立ち寄りの最終 `departureTime` で種をまき直す。記録終了で破棄する。

これで削除した立ち寄りの区間は境界より手前になり、検出スライスに入らず**復活しない**。過去区間を舐め直さない
ので検出コストは「直近の確定立ち寄り以降の点数」に比例する。1 つの変更で復活バグと全再計算の両方を解く。

## Alternatives（検討した没案）

- **件数基準のまま、追記の判定だけ直す（時刻フィルタ）** … `arrival > 境界` で追記を絞れば復活は防げるが、
  検出自体は全点のままで**全再計算が残る**。復活と性能は同根（削除耐性の境界）なので、境界を検出にも使う方が素直 → 却下。
- **境界を DB 列で永続化する（v8 マイグレーション）** … プロセス kill＋末尾削除直後クラッシュという端まで完全に
  堅牢。だが記録中セッションはプロセス継続が普通で、その端の発生確率は低い。バグ修正にマイグレーションは重い → 却下（案A＝メモリ保持を採用）。
- **削除を tombstone として永続化し、検出時に突き合わせる** … 意図を正確に残せるが、テーブル追加・突き合わせ処理と
  複雑さに見合わない。境界（高水位）で同じ効果が軽く得られる → 却下。
- **記録中は自動保存せず、終了時（`isFinal`）に一括確定** … 全再計算は消えるが「立ち寄り中」ライブ表示や
  記録中の一覧が出せなくなる（既存の体験を落とす） → 却下。

## Consequences（結果・トレードオフ）

- **復活バグの解消**: 記録中に手で消した立ち寄りは、中間・末尾いずれも再検出されない。
- **性能改善**: 毎ティックの `detect` 対象が「直近の確定立ち寄り以降」に縮む。過去の確定区間は再スキャンしない。
- **既知の端（案A のトレードオフ）**: 記録中にプロセスが kill され、かつ**末尾の立ち寄りを削除した直後に
  クラッシュ**した場合のみ、DB 最終 departure で種をまき直すためその 1 件が再検出されうる（中間削除は影響なし）。
  完全に塞ぐには境界の DB 永続化（v8）が要る。必要になったら本 ADR を Superseded にして作り直す。
- **`StopDao.countByTrack` はライブ検出からは不要**になった（差分判定を境界に置き換えたため）。
- 再解析（`detectMissingStops`／`addStops`・非破壊）は**全点**で検出するが、**記録中は候補を境界以前
  （確定済みの過去）だけに絞る**。ライブ検出が受け持つ末尾・滞在中を候補から外し、二重登録を防ぐため
  （境界が削除で下がらない性質を、記録中の再解析でも同じく利用する）。終了済みの経路は境界エントリが無いので
  全点が対象＝従来どおり。ユーザーが記録中に誤って消した過去の立ち寄りは、境界以前なので候補に残り opt-in で戻せる。
