# 地図の上の UI の設計

**何が起きるかは [../specs/map.md](../specs/map.md) / [../specs/screens.md](../specs/screens.md) を正とする。**
ここには、画面をまたいで共有している部品と、その置き方だけを書く。

---

## 地図描画の共通化

記録画面と経路詳細は**別画面**（記録＝ライブ・片手／詳細＝事後の見直し・編集）だが、
経路の描き方は共通コンポーネント `presentation/common/RouteMapContent` に一元化して見た目を揃える。

各画面は**自前の `GoogleMap` の中で** `RouteMapContent` を呼ぶ。カメラの挙動が違うため
（記録＝現在地追従／詳細＝経路にフィット）、地図そのものは共有しない。

描画順は 確定立ち寄りの帯 → 立ち寄り中の帯 → 軌跡 → 開始/終了マーカー → 立ち寄りマーカー（番号）
→ 立ち寄り中マーカー（滞在時間ラベル）。記録画面は端末の現在地ドットがあるので終了マーカーを出さない
（`showEndMarker = false`）。

マーカーは**形で「確定＝丸／これから決める＝ピン」**を表す（→ [ADR-0018](../adr/0018-marker-shape-conveys-certainty.md)）。
ピンは `MapPinMarker` が Canvas で描く（Google 標準ピンは使わない）。ピンの**先端**と丸バッジの
**下端**が、そのままマーカーの基準点（既定で下端中央）に来るよう寸法を組んでいる。

**一覧をマーカーにするときは `key()` で 1 件ずつ独立させる。** 付けないと Compose はマーカーを
並びの位置（スロット）で使い回すので、途中に要素が増えるとスロットの担当が入れ替わり、`remember` で
作っている `MarkerState` が別インスタンスに差し替わる。maps-compose の `Marker` は 1 つの
`MarkerState` に紐づく前提なので、差し替えるとマーカーが地図から外れる。立ち寄りで踏むと
**ピンが消えて番号が飛んで見える**（一覧の番号は正しいのに地図だけ 1・3・4 になる）。

マーカーは `MarkerComposable` を直に呼ばず、**`MapMarker`（`presentation/common/MapInfoWindow.kt`）で置く**。
タップで出る吹き出し（InfoWindow）は Compose ではなく地図が出しているのでシステムバックの対象にならず、
そのままだと地図の別の場所をタップするまで消えない。`MapMarker` は開いた吹き出しを
`MapInfoWindowState` に覚えさせ、**バックで閉じられるようにする**。状態は `rememberMapInfoWindowState()`
で **GoogleMap 1 つにつき 1 つ**作り、その地図のマーカー全部に渡す（吹き出しは地図全体で同時に 1 つしか
出ないので、覚えるのは 1 件でよい）。

マーカーのタップはシートと吹き出しを**同時に**出すので、**バック 1 回で両方畳む**。バックは最後に
登録されたハンドラ（＝シート）が受けるため、シート側で `CloseInfoWindowWithSheet` を呼び、
シートが composition から外れるときに吹き出しも閉じる。これが無いと 2 度押しになる。
シートの状態は画面が持ち、地図の composable には引数で渡す（`TrackingMapView` / `TrackMapView`）。

例外は**場所詳細の主マーカー**。画面を開いた時点で吹き出しを出し（`markerState.showInfoWindow()`）、
`dismissWithBack = false` で**バックの対象から外す**。下のシートと同じ場所を指していて画面の一部
なので、自分でタップして開き直しても扱いは変えず、バックは常に画面を戻す。別の場所のシートを開くと
地図が勝手に閉じてしまうので、そのシートを閉じてこの場所に戻ったら出し直す。

「閉じた」通知は**どのマーカーのものか必ず見る**。別のマーカーをタップしたときは
「B のタップ → B が開く → A が閉じる」の順で来るので、A の通知で無条件に忘れると開いたばかりの
B を取りこぼし、バックで閉じられなくなる。

登録済みの場所のマーカーは `RegisteredPlaceMarkers` に切り出し、**トラックが無くても**
（記録開始前など）単独で描けるようにしている。**色＝訪問状態／グリフ＝業種／右上の旗＝行きたい**の
3 軸で描き分け、訪問・行きたいの判定は「場所」タブの `PlaceListItem` と揃える。立ち寄りと重なった
ときは立ち寄りを前面にする。

`RegisteredPlaceMarkers` は、画面上で近い場所を**件数入りの丸（まとまり）**にまとめて描く
（→ [ADR-0028](../adr/0028-cluster-registered-place-markers.md)、仕様は [specs/map.md](../specs/map.md)）。
まとめる計算は `presentation/common/PlaceClustering.kt` の `clusterPlaces` で、地図にも Android にも
依存しない純粋な関数（ユニットテストあり）。

- まとめ直すのは**地図が止まったとき（`isMoving` が false の間のズームの段が変わったとき）だけ**で、ズームは 0.5 段に
  丸めて使う（`clusterZoomLevel`）。ピンチやまとまりのタップで寄せている途中にまとめ直すと、
  マーカーを何度も作り直して地図の動きがもっさりする。地図を動かしただけではまとまりは変わらない。
- **マーカーの画像は見た目ごとに 1 回だけ描いて使い回す**（`MarkerIconCache`）。`MarkerComposable` は
  マーカー 1 つごとに ComposeView を作って画面に足し、描いてから外すので、まとめ直しで数十個を
  作り直すと地図が 1 秒近く止まっていた（場所 120 件で計測）。見た目は訪問状態 × 業種 × 行きたい、
  まとまりは件数 × 行きたいで決まるので、それをキーにする。キーに見た目を決める値が抜けると、
  違う見た目のマーカーに古い画像が出る。
- 1 件ずつのマーカーは**バッジの下に名前を添える**（仕様は [specs/map.md](../specs/map.md)）。名前は場所ごとに
  違うので、`MarkerIconCache.getLabeled` が、見た目ごとに 1 回だけ描いたバッジの画像の下へ Canvas で直に書き足す
  （名前ごとに Compose で描くと、場所の数だけ ComposeView を作ることになり地図が止まる）。白いフチ取りの濃い文字で、
  幅を超えたら `TextUtils.ellipsize` で省く。画像が下に伸びるので、`anchor` をバッジの下端
  （高さに対する割合）に合わせ、**マーカーが指す点を変えない**。吹き出しは画像の上端（＝バッジの上）から出る。
- 経路の**立ち寄りのマーカー**（`RouteMapContent`）も同じ `getLabeled` で名前を添える（番号ごとにバッジを 1 回描く）。
  立ち寄り中のバッジは滞在時間が 1 分ごとに変わって使い回せないので、`createLabeled` でキャッシュに入れずに描き、
  `remember(滞在時間, 名前)` で変わったときだけ描き直す（キャッシュに入れると滞在が長いほど画像が溜まる）。
- 1 件・まとまりとも `key(entry.mapKey)` で独立させる。**`key` は `when` の外に置く**: 分岐の中に置くと
  Compose は分岐の並びの位置で見分けるので、まとめ直しで並びが変わると残っているマーカーまで作り直され、
  タップして寄せた直後に吹き出しが消えていた。
- 1 件ずつに戻ったマーカーは `MapMarker`（描き済みの画像を受け取る版）で置く。
  まとまりから外れてもタップの意味（編集／紐付け）と吹き出しのバックでの閉じ方は変わらない。
- まとまりは吹き出しを出さないので、`MapMarker` ではなく素の `Marker` を置き、クリックで
  `true` を返して地図の既定の挙動（吹き出し・カメラ寄せ）を止める。寄せ方は自前で
  `newLatLngBounds` に animate する。
- 登録済みの場所（1 件・まとまり）は `REGISTERED_PLACE_Z_INDEX`（0）で、他のマーカーより奥に描く。他のマーカーは
  `MapMarker` の既定の `DEFAULT_MARKER_Z_INDEX`（1）で 1 つ上に置く。ズームの段が変わるたびに作り直すので、描く順だけに
  頼ると、後から足されたこちらが立ち寄りの前に出てしまう。**負の zIndex は使わない**: 地図（LATEST レンダラー）は
  負の値を効かせず、0 と同じく後から足した方を前に出す（-1 にしていた頃は、まとまりが立ち寄りや終点の上に出ていた）。
- 記録画面は現在地に追従している間、位置の更新ごとにカメラを現在地へ戻す。まとまりのタップで寄せたら
  追従を止める（`onClusterExpand`）。寄せたのはジェスチャーではないので、手で動かしたときの判定には掛からない。
- まとまりが、吹き出しの出ていたマーカーを飲み込むことがあるので、まとまりのタップで吹き出しを閉じる。
  ズームアウトでマーカーが消えたときは `MapInfoWindowState.onMarkerDisposed` が拾う。

業種のグリフは `PlaceCategoryGroup`（Google の `primaryType` を束ねた分類）から引く。対応付けを
DB に持たないのは、`R.drawable` の ID を DB に入れられず結局コードで分岐するため
（→ [ADR-0017](../adr/0017-normalize-place-category.md)）。旗を右上へ逃がしているのは業種が
グリフを占めたからで、余白を左右対称に取って下端をバッジに揃え、**マーカーの基準点（下端中央）を
ずらさない**ようにしている。

マーカーは**画像の矩形**でタップを拾い、地図のタップより先に判定される。形（丸・ピン）で当たり判定を
切り抜くことはしない。Maps SDK にその API が無く、マーカーのクリックで `false` を返しても地図のタップには
回らないため、自前で座標を変換して [ADR-0009](../adr/0009-map-tap-behavior.md) のタップ挙動を持ち直すことに
なるから。タップ領域は小さくしない方がよい（推奨 48dp 以上）こともある。代わりに**画像の透明な余白を
増やさない**: 旗は丸のフチに半分かぶせ、余白を 4dp に留めている。

## 非モーダルのシート

地図の上に出すシートは、標準の `ModalBottomSheet` ではなく**自前の `FloatingSheet`**
（`presentation/common/`）を使う。スクリムがタップを吸ってしまい、シートを出したまま地図を
操作できないため（→ [ADR-0010](../adr/0010-non-modal-map-sheets.md)）。

- 3 段階（`SheetDetent`: HIDDEN / PEEK / FULL）。畳みきったときに戻すボタンは `restoreLabel` を
  渡すとシート側が出す（各画面で書かない）。
- 段はつまみのドラッグのほか、**つまみの行のタップ（ハーフ⇔フル）と右端の ▼（畳む）**でも変えられる
  （→ [ADR-0042](../adr/0042-primary-action-moves-with-sheet.md)）。▼ は `restoreLabel` のあるシートだけに出す
  （戻せないシートを畳ませない）。中身の量が決まった小さなシートは `rememberFixedFloatingSheetState(高さ)` で作る
  （ハーフとフルが同じ高さなので、タップでは広げない）。
- **地図に `contentPadding` としてシートの高さを渡す**。これでカメラの中心が見えている領域の中心に来て、
  タップした地点がシートの下に隠れない。高さは呼び出し側が `sheetState` から取れるよう、
  シートの状態を**外に持たせる**（`rememberFloatingSheetState` を画面側で持つ）。
- 用途ごとに 2 種類ある。**場所シート**（`presentation/places/PlaceActionSheet`）と
  **立ち寄りシート**（`presentation/stops/ManualStopSheet`）。滞在区間の調整は場所の登録に要らないので、
  同じシートにまとめない。
- 入力フォームは `PlaceFormBody` を共有する（追加・検索・編集・地図タップで同じ見た目）。
- **登録済みの場所を編集する部分は `PlaceEditorBody` 1 つに集約する。**場所タブの詳細画面と、
  地図のマーカーをタップして出るシートは、これを呼ぶ器が違うだけ（→ [ADR-0019](../adr/0019-single-place-editor.md)）。
  片方にだけ機能を足さないこと。

## 地図の画面の型の部品

地図の画面の区画（[ui-direction.md](ui-direction.md) の「地図の画面の型」）ごとの部品。記録画面（#193）から使い、
経路詳細・場所詳細・履歴と場所の地図も順に載せ替える。

| 区画         | 部品（`presentation/common/`）                                                          | 中身                                                                                         |
| ------------ | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 上・上の下   | `MapTopBar`（`MapTopBar.kt`）                                                           | 左（戻る＋見出し、または検索の入口）・右端（レイヤー・⋮）・その下に今の状態を縦に積む        |
| 上の下       | `MapNoticeBanner`（同）                                                                 | 1 行の帯。押すと詳しい画面へ（›）。うまくいかなかった知らせは `isError`                      |
| レイヤー     | `MapLayersButton`・`RegisteredPlacesLayerItems`・`MapLayerActionItem`（`MapLayers.kt`） | ［≋］と開くパネル。登録済みの場所の表示・絞り込みは共通、ほかは画面ごとの行                  |
| 右下         | `MapControls`・`MapRoundButton`（`MapControls.kt`・`MapTopBar.kt`）                     | 地図の操作を縦に積む。`bottomInset` にいま出ているシートの高さ（段の確定値）を渡して沿わせる |
| シートの脇役 | `MapSideActions`（`MapControls.kt`）                                                    | シートの中の脇役の操作を横に並べる器。#201 で浮かぶツールバーに差し替える                    |

- 右下の操作と主役の丸は、シートの**段の確定値**に合わせて動く（ドラッグ中の高さを外で読むと地図ごと再コンポーズされて
  カクつくため → 「非モーダルのシート」）。畳んだシートは戻すボタンの分（`SheetRestoreButtonInset`）だけ上げる。
- 記録画面の検索の入口（「検索して登録」の窓と「地域へ移動」の地球）は `TrackingSearchEntry` 1 つにまとめてある。
  検索窓を 1 つにするとき（#192）は、その中身を差し替える。

## 一覧のタブの地図表示

場所タブと履歴タブは、一覧表示と地図表示を切り替えられる。その器と地図まわりは `presentation/common/` の
部品を使い、タブごとに書かない。

- **見せ方は `ListMapMode`**（`ListMapToggle.kt`）。SavedStateHandle には enum の名前で保存するので、値の名前を変えない。
- **`ListMapLayout`** が、地図を一度開いたら一覧の裏に残し（作り直すと地図が出るまでちらつく）、一覧で裏の地図を隠して
  触れないようにする。地図表示のときのシステムバック（一覧へ戻す）は呼ぶ側で持つ。戻るの優先は登録の順で決まり、
  絞り込みの欄を閉じる戻る・吹き出しを閉じる戻るをそれより後に登録するため。
- **`ListMapOverlay`** が、地図に重ねる見出し・検索・絞り込みの外枠と、たたんだ帯（文言は `listMapSummary`）。
  高さを返すので、地図の `contentPadding` の上に渡す。
- **カメラは `ListMapCamera`**（`MapCamera.kt`。地図表示の外で持ち、一覧に切り替えても・詳細から戻っても範囲を保つ）。
  同じファイルに、既定の位置 `DefaultMapLocation`、`GeoBounds` と `LatLngBounds` の変換、現在地を一度だけ取る
  `requestCurrentLatLng` がある。
- 重ねた経路の「この経路の全体を見る」（線を読み終えてから寄せる）は `TrackFocusEffect`（`presentation/tracking/TrackOverlay.kt`。
  重ねる経路の状態と同じ場所）で、記録画面と履歴の地図表示が使う。

## 画面をまたぐ部品の置き場

| 置き場                 | 中身                                                                  |
| ---------------------- | --------------------------------------------------------------------- |
| `presentation/common/` | ドメインに依存しないもの（`FloatingSheet`・地図描画・確認ダイアログ） |
| `presentation/stops/`  | 立ち寄りの UI（シート・区間エディタ・付け替えダイアログ）             |
| `presentation/places/` | 場所の UI（一覧・詳細・場所シート）                                   |

滞在区間の調整（スライダー＋到着/出発の ＋/− 微調整）は `StopRangeEditor`
（`presentation/stops/ManualStopRange.kt`）に切り出し、記録中・経路詳細の**両方の手動追加で使う**
（軌跡点が 2 点未満のときだけ推定にフォールバック）。

## 表示トグルの保存先

「登録済みの場所を表示」の ON/OFF は **Room ではなく `SharedPreferences`** に持つ
（`SettingsRepository` / prefs 名 `pathly_settings`）。トグルは **UI の表示設定**であって
場所データではないため、DB には持たせない。GPS 記録間隔と同じ扱い。

- **画面ごとに独立**して保持する。画面は `MapSurface`（`RECORDING` / `HISTORY` / `PLACE_DETAIL`）で表す。
- 各画面の ViewModel が購読し、地図上のトグルで書く。プロセスをまたいで保持される。

## アイコンとテーマ

- **Material Icons は使わない**（非推奨のため）。`res/drawable` のベクター＋`painterResource` で足す。
- テーマは `PathlyAndroidTheme` に統一。色・文字・角丸は `MaterialTheme` から、余白・影は `PathlySpacing`・`PathlyElevation`、
  地図に描くものの色は `PathlyMapColors` から取り、部品に数値や色を直書きしない（値は [specs/screens.md](../specs/screens.md#デザイントークン)、
  理由は [ADR-0040](../adr/0040-design-tokens-indigo-fixed-colors.md)）。既定は Pathly の色で、設定でダイナミックカラーに切り替えられる。
- **Material 3 Expressive を使う**（→ [ADR-0041](../adr/0041-adopt-material3-expressive-after-stable.md)）。Compose Material 3 の 1.5.0 安定版が
  来てから #201 で入れる。それまでに作る部品のうち、**地図の画面の脇役の操作**（浮かぶツールバーにする）・**右下の追加の入口**（FAB のメニューにする）・
  **一覧のツール行**（ボタンのグループにする）・**読み込み中の表示**は、あとで中身を差し替えるだけで済むよう、それぞれ 1 つの Composable にまとめて作る。
