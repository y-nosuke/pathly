# 0046. 選んだ地域の境界は Maps SDK の境界のスタイルで描き、マップ ID は境界を描く地図だけに付け、描いている間だけ地図を明るくする

- Status: Accepted
- Date: 2026-11-25

関連: 地域へ移動と目印は [0032](0032-jump-to-region-by-places-autocomplete.md)・[0043](0043-multiple-region-markers-kept-in-memory.md)、
場所一覧の見出しから地図で見るのは [0045](0045-region-header-map-fits-whole-region.md)、費用の考え方は [0014](0014-place-naming-cost-policy.md)、
地図の色は [0040](0040-design-tokens-indigo-fixed-colors.md)。仕様は specs/map.md「地域へ移動」・specs/screens.md「5. 場所画面」。

## Context（背景）

記録画面の「地域へ移動」や場所一覧の地域の見出しから地図を移しても、どこからどこまでがその地域なのかは地図から読み取れない（#157）。
Google マップのアプリのように、選んだ地域の境界を描きたい。

調べて分かった制約:

- Places API は境界の形を返さない。Maps SDK for Android の**境界のデータドリブン スタイル**（feature layer）なら、Place ID を指定して
  国・都道府県（行政区画レベル 1）・レベル 2・市区町村（地域区分）の境界を塗れる。変えられるのは線の色・太さと塗りの色だけで、点線にはできない。
- 使うには**マップ ID**（Cloud Console で境界のレイヤーを有効にしたスタイルを紐づけたもの）が要る。マップ ID を付けた地図の読み込みは
  Dynamic Maps の SKU（月 10,000 回まで無料）に数えられる。付けない地図は Maps SDK の SKU で無制限に無料。
- 境界のレイヤーは**明るいスタイルでしか効かない**（Experimental）。端末によっては使えない（新しいレンダラーが要る）。
- Pathly の地図は配色を指定しておらず、既定の「端末に合わせる」で**ダークモードでは暗い地図**になる
  （0040 は「地図の地は明暗で変わらない」としていたが、実際は変わっていた。2026-11-25 にエミュレータで確かめた）。

## Decision（決定）

- **境界は Maps SDK の境界のスタイルで描く。** 選んだ地域の Place ID と同じ地物だけを、目印と同じ藍（`PathlyMapColors.Region`）の
  実線と薄い塗りで描く（塗りは小さい段ほど濃くし、入れ子で出すと中の地域が濃く見える）。使うレイヤーは国・行政区画レベル 1・レベル 2・地域区分の 4 つ（郵便番号・学区は使わない）。
  - Place ID は今ある Places の呼び出しで手に入るものを使う（記録画面は Autocomplete の候補、場所一覧の見出しは範囲を引くときの候補）。
    境界のために呼び出しは増やさない。Place ID は保存しない（0043 と同じく、メモリに持つだけ）。
  - 境界が出ないとき（対象外の地域・未対応の端末・マップ ID が未設定・オフラインで Place ID が無い）は、何も言わずに今までどおり移すだけにする。
- **マップ ID は境界を描く地図（記録画面・場所一覧の地図表示。#272 で計画の詳細も）だけに付ける。** 鍵の扱いは API キーと同じで、`local.properties` の
  `GOOGLE_MAPS_MAP_ID`、CI は Secret の `GOOGLE_MAPS_MAP_ID`。空ならマップ ID の無い今の地図になる。
- **境界を描いている間だけ、その地図を明るい配色にする。** ふだんは今までどおり端末の明暗に合わせる。
  記録画面は地域の目印が 1 つでもある間、場所一覧の地図は境界のチップが出ている間。
- 場所一覧の地図の境界は 1 つで、ツール行の下に地名と × のチップを出す。× と一覧表示に戻ったときに消える。

## Alternatives（検討した没案）

- **境界のデータ（国土数値情報など）をアプリに入れ、ポリゴンを描く** … 点線にもでき、暗い地図にも描けるが、データが大きく、
  日本しか描けず、更新も要る → **却下**。
  ただし「データが大きい」は全国の市区町村を全部入れる前提での見立て。Google の境界で描けない政令市の区だけなら、
  間引けば数百 KB〜1 MB 程度の見込みで、区の再編もまれなので更新の手間も小さい。区だけをこの方法で足す案は #253 で考える。
- **すべての地図にマップ ID を付ける** … 境界を描かない地図（履歴・経路詳細・場所詳細など）まで Dynamic Maps の回数に数えられる → **却下**。
- **境界を描く地図はいつも明るくする** … 作りは単純だが、ダークモードで記録画面と場所一覧の地図だけが明るく、ほかの地図と揃わない → **却下**。
- **ダークモードでは境界を描かない** … 地図の見た目は変わらないが、ダークモードを使っていると境界が見られない → **却下**。
- **Text Search で地名から Place ID を引く（場所一覧の見出し）** … Issue で考えていた案。0045 で範囲を引くときの候補に Place ID が
  もうあるので要らない → **却下**。

## Consequences（結果・トレードオフ）

- 都道府県・市区町村・国・海外の都市（市区町村の段まで出る国）の範囲が地図で分かる。政令市の区（sublocality）は出ない見込み。
- 記録画面と場所一覧の地図の読み込みが Dynamic Maps の回数に数えられる（一人で使う回数なら無料の枠に収まる見込み）。
- ダークモードでは、地域を選ぶと地図が明るく切り替わる（境界を外すと暗く戻る）。
- 境界のレイヤーは Experimental なので、SDK の更新で見え方が変わることがある。
- 点線にはできない（Google マップのアプリの赤い点線とは見た目が違う）。
