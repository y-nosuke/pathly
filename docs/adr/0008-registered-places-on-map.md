## Context（背景）

`googlePlaceId` を持たない手動操作（空タップ・手入力）は座標同定に頼る（[ADR-0006](0006-place-identity-by-googleplaceid.md)）。
だが**地図に既存の場所が見えない**と、近くに登録済みがあることに気づかず**重複 place を増やす**。
また、オフライン記録の place は**未解決**のまま残り、暫定の GPS 座標のままで精度も低い。

## Decision（決定）

- **登録済みの場所を地図にマーカー表示**（記録・経路詳細・場所詳細）。ON/OFF は**画面ごとに独立**して
  `SharedPreferences` に保存（UI 設定なので Room には持たせない）。状態が分かるよう**色（訪問済み/未訪問）と
  グリフ（行きたい=旗/それ以外=ピン）**で描き分ける。
- **手動追加でマーカーをタップ → 既存 place へその立ち寄りを紐付ける**（`addManualStopForPlace`。新規 place を作らない）。
- **表示 OFF のフォールバック**として、`ID` 無しの手動追加の確定時に**近接確認**（半径＝検出半径 50m）を行い、
  既存があれば「**紐付け／新規**」を出す。「新規」は座標同定をバイパスして必ず新規 place を作る。
- **解決・紐付けが成功したら place の座標を施設の正確な座標（Places の LOCATION）へ置き換える**
  （暫定 GPS より地図・重複判定が正確）。
- **起動時に未解決 place を一括解決**（全経路で `place_resolutions` 行が無い立ち寄り place を Places で命名。
  オフライン時は各 place で no-op ＝行を残さず次回起動で再度拾う）。

## Alternatives（検討した没案）

- **ビューポート絞り込み／マーカークラスタリング** … 場所が数千件規模になるまでは全件でも十分。今は入れず、
  重くなったら対応（設計書に注記）→ 保留（却下ではなく後回し）。
- **座標を上書きしない** … 暫定 GPS のままで地図位置・30m 判定がずれる → 却下。
- **解決は経路単位（手動ボタン）のみ** … 手動登録・未オープンの経路が漏れる。起動時の全件キャッチアップで拾う → 補完。
- **近接確認を表示 ON でも出す** … 見えているのに確認は冗長。ON はそのまま新規が自然 → 却下（[ADR-0009](0009-map-tap-behavior.md)）。

## Consequences（結果・トレードオフ）

- 近くの既存に気づけて重複を防げる。解決で名前・住所・カテゴリ・正確な座標が埋まる。
- 全マーカーをコンポーズするため、**場所が非常に多いと描画コスト**が上がる（将来クラスタリング等が必要）。
- Nearby は有料なので、起動時解決は**オンライン時のみ・place 1 件 1 回**に限定（解決済みは行があるので再課金しない）。
