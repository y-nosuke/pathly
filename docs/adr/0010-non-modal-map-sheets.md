# 0010. 地図の上に出すシートは非モーダル（自前）にする

- Status: Accepted
- Date: 2026-08-13

関連: 地図タップの挙動は [0009](0009-map-tap-behavior.md) / [../designs/map-tap-behavior.md](../designs/map-tap-behavior.md)。

## Context（背景）

地図上の 1 点をタップして出す「場所シート」（`PlaceActionSheet`）は `ModalBottomSheet` で、
`skipPartiallyExpanded = true` ＋既定のスクリムだった。**タップした地点の周りが見えない**ため、
どこを登録しようとしているのか確認しながら操作できない。

このシートは記録画面・経路詳細・場所詳細の 3 画面で共有しており、影響も 3 画面に及ぶ。

「地図を見ながら操作したい」という要求に対して、標準の `ModalBottomSheet` でどこまでできるかを
Material3 1.4.0 の実装を読んで確認した。

- `Scrim` は `if (color.isSpecified)` で囲まれている。`scrimColor = Color.Unspecified` なら
  **スクリムの描画もタップ処理も生成されない**。
- 1.4.0 には `ModalBottomSheetProperties(shouldDismissOnClickOutside = false)` もあり、
  **スクリムを残したまま「外側タップで閉じる」だけを止められる**。
- ただし `ModalBottomSheet` の実体は `ComponentDialog` のフォーク（`ModalBottomSheetDialogWrapper`）で、
  **独立した Android ウィンドウ**として表示される。スクリムを消してもタッチイベントはダイアログの
  ウィンドウが受け取り、背後の Activity（＝地図）には届かない。

つまり標準部品では **「地図が見える」までは実現できるが、「地図をパン・ズームしながらシートを開いておく」は実現できない**。

なお、経路詳細の立ち寄り一覧では既に**自前のフローティングシート**（スクリム無し・3 段ドラッグ）を
使っており、アプリ内に 2 種類のシート機構が併存していた。

## Decision（決定）

**地図の上に重ねるシートは、標準の `ModalBottomSheet` ではなく自前の非モーダルシートで出す。**

- `presentation/common/FloatingSheet` に共通化する。開閉の段（隠す／ハーフ／フル）、ドラッグ操作、
  高さの状態（`FloatingSheetState`）をここにまとめる。
- 経路詳細の立ち寄り一覧シートと、場所シート（3 画面）の両方をこれに乗せる。
- 場所シートのようなフォームは `allowHidden = false`（ドラッグで隠しきれない）。
- 非モーダルなのでシステムバックは各シートが自分で受ける。

高さの読み取りはシートの内側に閉じ込める（外側で読むと、ドラッグ・アニメの再コンポーズが
地図まで波及してカクつく）。

## Alternatives（検討した没案）

- **`scrimColor = Color.Transparent`** … スクリムの色だけ透明にする。スクリム自体は残るため
  タップを吸い、地図は動かせず、触ると閉じる → **却下**（最初にこれを入れて、実際に煩わしかった）。
- **`scrimColor = Color.Unspecified`** … スクリムを生成しない。閉じなくはなるが、ダイアログの
  ウィンドウがタッチを受け取るため**地図は操作できない** → 却下。
- **`shouldDismissOnClickOutside = false`** … 同上。加えてスクリムが残るので地図が暗いまま → 却下。
- **`skipPartiallyExpanded` を外すだけ** … 半分の高さで開くので地図は見えるが、スクリムの問題は
  そのまま残る → 却下。
- **経路詳細の自前シートを ModalBottomSheet に寄せて統一する**（逆方向の統一）… 立ち寄り一覧は
  地図と連動して選択・スクロールするため、地図が触れないと成立しない → 却下。

## Consequences（結果・トレードオフ）

- 地図のパン・ズーム・タップがシートを開いたまま効く。3 画面すべてに一度に効く。
- アプリ内のシート機構が 1 つになり、経路詳細に散らばっていた状態管理（約 40 行）が共通側へ寄った。
  手動での立ち寄り追加や場所タブの追加フローも、同じ土台に乗せられる。
- **標準部品から外れる**ぶん、Material の更新に自動では追従しない。アクセシビリティ（フォーカス管理・
  読み上げ順）やプレディクティブバックも自前で面倒を見る必要がある。
- 「外側タップで閉じる」が無くなるので、**閉じる導線はキャンセルボタンとシステムバックだけ**になる。
  ここは実機で使ってみて、迷うようなら閉じるボタンの明示などを検討する。
