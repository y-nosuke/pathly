# 0011. 場所の座標は Places の施設座標を使い、地図アイコンの位置には合わせない

- Status: Accepted
- Date: 2026-08-14

関連: 座標を Google のものへ置き換える決定そのものは [0008](0008-registered-places-on-map.md)。

## Context（背景）

場所の座標には**出どころが 2 つ**ある。

- **施設の座標** … Places API が返す座標（`PlaceSearchResult.latitude/longitude`）。
  自動命名（`resolvePlace`）と「Google施設を選び直す」（`linkPlaceToGoogle`）はこれを採用する。
- **アイコンの座標** … 地図のアイコンをタップしたときに得られる座標（`PointOfInterest.latLng`）。
  地図の POI タップからの登録だけがこれを使う。

この 2 つは**同じ値とは限らない**。実測（清瀧神社・浦安）で、立ち寄りから自動命名された場所のピンが
地図の POI アイコンから数十 m ずれていた。別の施設を選び直すとピンはそちらへ飛び、もう一度
同じ施設を選び直すと元のずれた位置へ戻った。**保存も座標の更新も正常で、書き込む値が違うだけ**だった。
同じ施設を POI タップで登録すると、アイコンの位置に登録された。

どちらかが誤りというわけではない。施設の座標は Google が持つその施設の代表点で、経路検索なども
これを使う。アイコンの位置は地図がラベルを描くために選んだ点で、敷地のある施設（神社・寺・公園・
学校など）では両者が離れる。

## Decision（決定）

**場所の座標は施設の座標（Places API）を正とする。地図アイコンの位置には合わせない。**

「Google施設を選び直す」は Google のデータをそのまま採用する現状の動作を維持する。
見た目のズレは受け入れる。

## Alternatives（検討した没案）

- **「Google施設を選び直す」でアイコンの座標を書く** … **実装できない**。あのダイアログの候補は
  Places API（`SearchNearby` / `fetchPlace`）から取るため `PlaceSearchResult` しか無く、
  アイコンの座標は地図の上のアイコンをタップして初めて `PointOfInterest` として手に入る。
  ダイアログには地図が無いので、書き込む値そのものが存在しない → 却下。
- **POI タップで「登録済み」だったときに、その座標で上書きする** … アイコンの座標が手に入る唯一の
  経路なので技術的には可能。ただし「検索して追加」も同じ `registerPlace` を通り、そちらは施設の
  座標を渡すため、**最後に使った経路の値が採用される**ことになる。加えて「登録済みなら何もしない」
  という現在の素直な挙動を崩す → 却下。
- **アイコンの座標を取るための導線を足す**（例: 詳細の地図で対象施設をタップして位置を合わせる）
  … 画面の操作を増やしてまで解く問題ではない → 却下。

## Consequences（結果・トレードオフ）

- 敷地のある施設では、ピンが地図のアイコンから離れて見えることがある。**これは仕様**として扱う。
- 座標は Google の代表点なので、Google マップで開いたときや経路検索との整合は保たれる。
- **登録経路によって座標の出どころが違う**という非一貫性は残る。地図の POI タップで登録した場所は
  アイコンの座標、それ以外は施設の座標になる。同じ施設を両方の経路で扱っても
  `googlePlaceId` で同定されるため place は 1 つにまとまるが、**先に作られた方の座標が残る**。
- 場所の座標は 30m の同定にも使う。施設の座標が実際に立ち寄る場所（参道・入口など）から離れて
  いると、次の訪問で別の place として検出される余地がある。これは [0008](0008-registered-places-on-map.md)
  で座標を置き換えると決めた時点からある性質で、この ADR で新たに増える負担ではない。
