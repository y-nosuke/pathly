# 0053. 確認ダイアログは戻せない操作だけに出し、戻せる削除は取り消しのスナックバーで、組み立てる編集は「保存」で確定する

- Status: Accepted
- Date: 2026-11-28

関連: 計画の下書きは [0052](0052-plan-edits-saved-explicitly-with-drafts.md)。決まりの今の姿は
[designs/ui-direction.md](../designs/ui-direction.md) の「操作の確定のしかた」。#286 で決めた。

## Context（背景）

操作によって、押したらすぐ入るもの（#273 の経路の結び付け）、確認のダイアログを出すもの（付け替え・記録の停止）、
「保存」を待つもの（計画の編集 → 0052）、すぐ消して取り消しのスナックバーを出すもの（経路・場所・計画の削除）が混ざっている。
どれも筋は通っているが、出す・出さないの基準が無いので、作るたびに迷い、画面ごとに流儀がずれる
（前は経路の削除だけ確認ダイアログだった）。この後の #284（計画の編集の一つ戻す・進める）と #283（計画の完了・中止）も、
同じ問いに答える必要がある。

## Decision（決定）

上から順に当てはめ、最初に当たったものにする。

1. 本人にしか決められない分かれ道は、**選ぶダイアログ**を出す（確認とは分けて考える）。
2. 1 つのものを何手もかけて組み立てる編集は、**「保存」まで待つ**。待つのはその画面が編集しているものの中身だけで、
   ほかのものへの操作はすぐ入る。保存していない変更を捨てるときは聞く。保存までの操作には確認も取り消しも要らない。
3. それ以外は**すぐ確定**する。
   - 何も消えない・同じ手間でやり直せるなら、何も出さない。
   - 本人が入れたものが消える・まとまるが、アプリがその場で戻せるなら、**取り消しのスナックバー**を出し、確認は出さない（何件でも）。
   - 元に戻せない（全部の置き換え・控えを残さない削除・進んでいるものを終える）ときだけ、**確認ダイアログ**を出す。
4. 目の前に見えていないものに及ぶときは、押す前に注記で見せる。見せる所が無いときだけ確認ダイアログにする。

これを当てはめると、

- #284: 経路の結び付けは保存を待たずに入るもの（3）で、計画の中身ではないので、一つ戻すの対象にしない。
- #283: 完了・中止は状態の切り替えで、同じメニューから戻せる（3 の「やり直せる」）ので、確認を出さずにすぐ確定する。

## Alternatives（検討した没案）

- **消すもの・まとめるものはすべて確認ダイアログにする** … いちばん安全に見える → **却下**。確認は毎回出ると読まずに押す
  癖がつき、本当に戻せない操作の確認まで効かなくなる。取り消せるなら、間違えたときだけ戻せば済み、正しく押した大多数の手間が減る。
- **すべてすぐ確定し、取り消しのスナックバーだけにする（確認ダイアログを無くす）** … 流儀は 1 つにそろう → **却下**。
  読み込み（全部の置き換え）や異常終了の記録の削除のように、アプリが控えを持てない・持つと重いものがある。
  記録の停止は、移動中の誤タップで切れると同じ経路に戻れない。
- **何件にかかるかで分ける（1 件は取り消し、まとめて消すときは確認）** … → **却下**。戻せるかどうかは件数で変わらない。
  立ち寄りのまとめて削除も、控えておけばそのまま戻せる。
- **計画の画面での操作はすべて下書きに入れる（場所の登録・経路の結び付けも保存まで待つ）** … 画面の中で流儀がそろう → **却下**。
  場所や結び付きは計画の中身ではなく、保存せずに破棄したときに、登録した場所まで消えるのか残るのかが分からなくなる（0052・#273 と同じ判断）。

## Consequences（結果・トレードオフ）

- 新しい操作は、表に当てはめれば扱いが決まる。決まりから外れる操作は、直す Issue にする。
- 取り消しのスナックバーにする操作は、消すときに実体を控えて元の ID のまま戻す実装が要る（確認ダイアログより手間がかかる）。
- 取り消しはスナックバーが出ている間だけなので、気づくのが遅れたら手で直すしかない。それでも、戻せない操作を確認で守るほうを優先する。
- 「保存」を待つ編集では、途中の操作を戻す手段（一つ戻す → #284）が別に要る。
