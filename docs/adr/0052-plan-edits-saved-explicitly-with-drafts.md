# 0052. 計画の編集は「保存」で確定し、途中は下書きとして残せる

- Status: Accepted
- Date: 2026-11-27

関連: 計画のデータは [0050](0050-plans-as-ordered-items-with-optional-dates.md)、画面は [0051](0051-plan-tab-and-overlay-on-maps.md)。
仕様は [specs/plans.md](../specs/plans.md) の「保存と下書き」。#271 のスマホでの確認で決めた。

## Context（背景）

#271 の最初の形では、計画の詳細での変更（行を足す・並べ替える・日付を変える…）をその場で DB に書いていた。
スマホで試すと、計画は何度も組み替えながら考えるもので、

- 試しに動かした並びや日付も、そのまま計画になってしまう（元に戻すには覚えておくしかない）。
- （＋）を押しただけで「新しい計画」が増える。
- 考えている途中で手を止めたいが、途中のまま確定させたくはない。

という声が出た。

## Decision（決定）

- **詳細での変更は画面の中の下書きにだけ入れ、上のバーの「保存」で計画に書く。** 保存済みと違うときだけ押せる。
  （＋）で開いた新しい計画も、保存するまで作らない。
- 変更してから戻るときは、**保存・下書きに残す・破棄**（と編集を続ける）を聞く。
- **下書きに残す**と、編集の途中を `plan_drafts`（v22）に JSON で残す。計画ごとに 1 つ。一度も保存していない計画の下書きも持てる。
  開くと下書きの続きから始まり、帯で下書きだと分かるようにする。保存すると下書きは消える。
- 計画の削除は今までどおりすぐ消し、取り消しのスナックバーで戻す（下書きも一緒に消え、一緒に戻る）。

## Alternatives（検討した没案）

- **その場で書いて、取り消し（元に戻す）を積む** … 1 つ前には戻せるが、「この版で確定」「途中は残しておく」が言えない → **却下**。
- **下書きをアプリを使っている間だけ持つ（端末に残さない）** … アプリを閉じると考えていた途中が消える → **却下**（ユーザーの要望で残す）。
- **下書きを計画・行と同じ形の表で持つ**（`plan_draft_items` など）… 問い合わせはしやすいが、表が 2 つ増え、計画の表と同じ決まりを二重に持つ。
  下書きは開くときに丸ごと読むだけなので JSON で足りる → **却下**。
- **戻るときに黙って下書きに残す** … 残したつもりのない下書きが溜まる → **却下**（聞く）。

## Consequences（結果・トレードオフ）

- 計画を組み替えながら考えられ、確定は「保存」だけになる。
- 下書きの行は場所を id で指すだけなので、下書きの後に場所を消す・まとめると、開いたときにその行は無くなる
  （計画に入っている場所は自動では消えないが、下書きだけの場所は守られない）。困るようなら、下書きの場所も守る対象に入れる。
- 保存は行を丸ごと入れ替えるので、行の id は保存のたびに変わる（行の id を外から指すもの（#273 の結び付きなど）は作らない）。
