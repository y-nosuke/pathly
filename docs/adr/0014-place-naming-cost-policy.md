# 0014. 自動命名は Places を使い、オンライン時・place 1 件 1 回に限る

- Status: Accepted
- Date: 2026-07-24（記録は 2026-08-15 に遡って作成）

関連: 名前をどの列に入れるかは [0001](0001-place-data-separation.md)。

## Context（背景）

立ち寄りを検出しても、座標のままでは振り返りに使えない。「35.6581, 139.9021」ではどこだったか
思い出せない。**人が分かる名前**が要る。

ただし名前を引く手段は有料で、しかも Pathly は「月額 $0〜5 に収める」ことを前提にしている。
記録するたびに叩けば、立ち寄りの数だけ課金が積み上がる。

さらに厄介なのが、**POI が無い場所**（自宅の前・河川敷・駐車場）と**オフラインでの記録**である。
この 2 つを区別せずに「名前が無いから引き直す」と実装すると、POI が無い場所を永久に叩き続ける。

## Decision（決定）

**Places API (New) の Nearby Search で名前を引く。ただしオンラインのときだけ、place 1 件につき自動では 1 回だけ。**

「叩いたかどうか」は **`place_resolutions` の行の有無**で判定する。`name IS NULL` では判定しない。

| 状況             | `place_resolutions` | 自動で再取得   | 手動で再取得 |
| ---------------- | ------------------- | -------------- | ------------ |
| POI が見つかった | 行あり              | しない         | しない       |
| POI が無かった   | 行あり              | **しない**     | できる       |
| オフライン・失敗 | **行を作らない**    | する（復帰時） | できる       |

- 応答が返ったら、見つかっても見つからなくても行を作る＝二度と自動では叩かない。
- 通信できなかったときだけ行を作らず、次の機会に持ち越す。
- ユーザーが明示的に押したとき（「Googleで情報を取得」「Google施設を選び直す」）は、この制限の外。

## Alternatives（検討した没案）

- **Geocoder（無料・住所のみ）を使う** … 課金はゼロだが返るのは住所で、「スターバックス」
  「◯◯公園」のような**人が分かる名前**にならない。振り返りという目的を満たさない → 却下。
- **名前が null の place を対象に引き直す** … 素直だが、**POI が無い場所を毎回叩く**。
  「名前が無い」は「まだ引いていない」と「引いたが無かった」の両方を意味してしまう → 却下。
- **places に「試行済み」フラグを持たせる** … 判定はできるが、`places` に動的な状態が入る
  （[0013](0013-separate-place-stop-wishlist-tables.md) の方針に反する）→ 却下。ログとして別テーブルに分離した。
- **記録の完了時にまとめて引く** … 呼び出しは減らないうえ、記録中に「いまどこに居るか」を
  名前で出せない → 却下。滞在が 3 分を超えた時点で place を確定させ、その場で引く形にした。

## Consequences（結果・トレードオフ）

- 課金は「新しく訪れた場所の数」に比例し、同じ場所に何度行っても増えない。
- オフラインで記録しても、通信が戻れば名前が付く（`PlaceNameCatchUpWorker` が拾う）。
- **POI の無い場所は未命名のまま残る**。自動では二度と埋まらないので、必要なら手動の導線で埋める。
- 一度引いた施設情報は**古くなっても自動更新されない**（店名が変わっても追随しない）。
  気づいたら「Google施設を選び直す」で取り直す。
- 再解析の候補に添える名前は、この「1 件 1 回」の外側にある（[0012](0012-non-destructive-reanalysis.md)）。
