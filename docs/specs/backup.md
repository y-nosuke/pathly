# データの書き出し・読み込みの仕様

記録・場所・設定をまとめて 1 つのファイルに書き出し、あとで読み込んで元に戻す。
クラウド同期（Phase 3）が無い間の、**端末の故障・紛失・機種変更への備え**。

> 対応する要望: [../requirements.md](../requirements.md)（設定）。決定の背景は [ADR-0027](../adr/0027-data-export-import.md)。

---

## 何が入るか

| 入るもの                                                                       | 入らないもの                                     |
| ------------------------------------------------------------------------------ | ------------------------------------------------ |
| 経路・GPS 点（原データと補正後）・立ち寄り・場所・行きたい・訪問済み・施設情報 | 権限の許可（位置情報・通知・電池の最適化の除外） |
| 設定（記録間隔・位置の取り方・地図の表示）                                     | 地図の表示位置などの一時的な状態                 |

- ファイルは **zip 1 つ**（例: `pathly-backup-20260927-1030.zip`、開発版は `pathly-dev-backup-…`）。
- 中身は DB の写しそのまま。**人が読む形式（CSV・GPX など）ではない**。他のアプリで開くことは想定しない。

## 書き出す

設定タブの「データ」→「書き出す」。保存先は Android のファイル選択画面で**毎回本人が選ぶ**
（端末内・Google ドライブなど）。

- **記録中でも書き出せる**。押した時点の一貫した状態になる。
- 書き終えたら、**ファイルに入った件数**を見せる（何が入ったかをその場で確かめられるように）。

  ```text
  ・経路 31件（位置 26,283点）
  ・立ち寄り 68件
  ・場所 108件（行きたい 55件・訪問済み 38件）
  ```

- アプリが自動で書き出すことはない。

## 読み込む

設定タブの「データ」→「読み込む」でファイルを選ぶ。

1. ファイルを確かめ、**書き出し日時と、書き出し完了と同じ形の件数**を見せて、置き換えてよいか確認する
   （古い版で書き出したファイルに無い項目は出さない）。
2. 「置き換える」を選ぶと、**今のデータ（記録・場所・設定）をすべて**そのファイルの内容に置き換える。
   足し合わせはしない。
3. 置き換える前の状態はアプリ内に退避され、「**読み込む前の状態に戻す**」で戻せる（退避は直前の 1 回分だけ）。
4. 置き換えるとアプリが**再起動**する。

- **記録中（停止後の確定中を含む）は読み込めない**。
- リリース版と開発版のあいだでも読み込める（開発版に実データの写しを入れて試せる）。

### 読み込めないファイル

| 状況                                 | 伝えること                     |
| ------------------------------------ | ------------------------------ |
| Pathly の書き出しファイルではない    | 読み込めない                   |
| 今のアプリより新しい版で書き出された | アプリを最新にしてから読み込む |
| 知らない形式の版                     | アプリを最新にする             |
| 壊れている                           | 読み込めない                   |

古い版のアプリで書き出したファイルは読み込める（読み込んだあと、今の形へ移し替える）。

## 扱いの注意

- 書き出したファイルは**暗号化していない**。位置の記録がそのまま入っているので、置き場所・共有先に注意する
  （→ [security.md](security.md)）。
- アプリはファイルをどこにも送らない。保存先を選ぶのは本人。
