# 0037. 同じ施設と分かった場所は、まとめるか別のまま残すかをユーザーに選んでもらう（v21）

- Status: Accepted
- Date: 2026-11-14

関連: ひとつの施設を持てる場所は 1 つだけ（[0025](0025-one-place-per-google-facility.md)）、
空き地点からは施設を問い合わせない（[0034](0034-no-same-facility-check-on-empty-tap.md)）、
行きたいは行ったら終わる（[0036](0036-wishlist-ends-on-visit-and-keeps-history.md)）、
問い合わせは一度だけ（[0014](0014-place-naming-cost-policy.md)）。仕様は [../specs/places.md](../specs/places.md)。

## Context（背景）

[0025](0025-one-place-per-google-facility.md) で、ひとつの Google 施設を持てる場所は 1 つだけにした。
自動でまとめるのは「検出が作った・中身が空」の場所だけで、それ以外（地図で指して作った場所、名前・メモ・
行きたい・訪問済みの印を付けた場所）は**施設情報を付けずに残す**ことにした。機械では決めず人に委ねる、という判断だった。

ところが、委ねる先の手立てが無かった。

- 経路詳細の「場所を取得（未取得 N件）」に数えられ続け、押しても減らない。
- 押すたびに Google に問い合わせ直す（Places API の費用が毎回かかる）。
- 場所詳細には理由が出ない。「Googleで情報を取得」で同じ施設を選ぶと、断られて終わる。

[0034](0034-no-same-facility-check-on-empty-tap.md) で「作る前には止めない」と決めたので、
同じ施設の場所が 2 つになったときは、**分かったときに片づける**手立てが要る。

## Decision（決定）

**同じ施設と分かったら、次の 3 つからユーザーに選んでもらう。**

1. **「◯◯」にまとめる**（同じ場所だった）。
2. **別の施設を選び直す**（Google が隣の店などを拾った）。既存の「Google施設を選び直す」を開く。
3. **施設情報なしで、別の場所として残す**（どちらでもない）。二度と聞かず、「未取得」にも数えず、問い合わせ直さない。

### いつ聞くか

- **その場で操作したとき**（経路詳細の「場所を取得」、場所の編集部の「Googleで情報を取得」「Google施設を選び直す」）は、
  その場でダイアログを出す。「場所を取得」で何件も見つかったら、1 件ずつ続けて聞く（「あとで」で閉じられる。まとめたときは取り消せるようにいったん閉じる）。
- **裏の自動の名前付け**（記録中のライブ検出・WorkManager のキャッチアップ）で分かったときは、聞かずに記録だけする。
  場所詳細・経路詳細を開いたときに「確認待ち」として出す。Google には問い合わせ直さない。

### 記録の持ち方（`place_resolutions` に 2 列を足す）

| 列                          | 意味                                                                      |
| --------------------------- | ------------------------------------------------------------------------- |
| `sameFacilityGooglePlaceId` | 問い合わせで分かった施設を、既に別の場所が持っていたときの、その施設の ID |
| `keptSeparate`              | 3 を選んだ（施設情報なしで別の場所として残す）                            |

- 相手は **place の id ではなく施設の ID で持つ**。相手は `google_places` から引く。相手を消した・相手が別の施設に
  付け替わったときに、記録が古い相手を指したままにならない（引けなくなれば確認待ちから外れ、「未取得」に戻って
  「場所を取得」で問い合わせ直せる）。
- **確認待ち**＝`sameFacilityGooglePlaceId` があり、`keptSeparate` が偽で、その施設を自分以外の場所が持っている。
- 確認待ちと 3 を選んだ場所は「未取得」に数えず、「場所を取得」の対象からも外す（問い合わせ直しても付かないため）。
- 2 で別の施設に紐付けたら、解決記録を書き直すので確認待ちは消える。
- v21 のマイグレーションでは埋めない。これまでに同じ施設で断った場所は、どの施設とぶつかったかを持っていない。
  「未取得」に数えられたままなので、「場所を取得」を押すと問い合わせ直し、そこで選択肢が出る。

### 「まとめる」の決めごと（なるべく何も失わない）

まとめられる方（確認待ちの場所）は消え、相手（施設を持っている方）が残る。

- 立ち寄り・行きたいの履歴は、すべて残る方へ付け替える。
- 名前・メモは残る方を優先し、残る方が空ならもう一方を使う。メモが両方にあれば、残る方を先にしてつなげる。
- 行きたい・訪問済みの印は、どちらかにあれば付ける。行きたいが両方にあれば、優先度は高い方。
- 施設情報は残る方のもの。残る方に無ければ、もう一方のものを移す（#86 の手でまとめるときのため）。
- どちらかが自分で作った場所（`USER`）なら、残る方も `USER` にする（自動回収から守る）。
- 付け替えた立ち寄りが、残る方の行きたいを「行った」で終わらせることがある（[0036](0036-wishlist-ends-on-visit-and-keeps-history.md)。
  入れた後の立ち寄りが記録されたことになるため）。
- 1 つのトランザクションで行う（`PlaceMergeDao`）。途中で止まって半端な状態にならないように。
- スナックバーの「取り消す」で戻せる。取り消しは、まとめる前の両方の場所の行一式（場所・行きたい・訪問済み・
  行きたいの履歴・解決記録・施設情報）と付け替えた立ち寄りの id を控え、**元の id のまま**入れ直す
  （場所の削除・立ち寄りの統合の取り消しと同じ方式）。

## Alternatives（検討した没案）

- **確認待ちを別テーブルに持つ** … 「相手」と「決めた結果」だけのために表を増やすことになる。解決記録は
  「問い合わせた結果」を持つ場所で、相手が分かったのも問い合わせの結果なので、ここに足す → 却下。
- **相手を place の id で持つ** … 相手を消す・相手が施設を付け替えると、古い相手を指したまま残る。外部キーで
  消すと、今度は「同じ施設の相手がいなくなった」ことが分からず、問い合わせ直せなくなる → 却下。
- **裏の名前付けでも通知で聞く** … 通知で知らせる機能は作らない方針（自動で動くことを優先）。開いたときに出せば足りる → 却下。
- **3 を選んだ場所を消す** … 立ち寄りは必ずどこかの場所に紐づくので消せない。施設情報が付かないだけで、場所は残す → 却下。
- **「まとめる」でまとめられる方の名前・メモを捨てる** … 自分で付けたものが黙って消える。メモはつなげ、名前は残る方が
  空なら引き継ぐ → 却下。

## Consequences（結果・トレードオフ）

- 押しても減らない「未取得」が残らない。確認待ちと別のまま残した場所は数えず、問い合わせ直さない（Places の費用も減る）。
- 同じ施設の場所を、その場か、あとで開いたときに 1 つにまとめられる。まとめる処理（`PlaceRepository.mergePlaces`）は
  #86（Google で見分けられない場所を手でまとめる）でも使い回せる形にしてある。
- 3 を選んだ場所には施設名が付かないまま残る。名前が要るなら自分で付ける。もう一度施設を付けたくなったら、
  場所詳細の「Googleで情報を取得」を使う（その場の操作なので、同じ施設ならまた聞く）。
- まとめで残る方の行きたいが「行った」で終わると、取り消すまで行きたいの旗が外れる。取り消せば戻る。
- 取り消せるのは直近の 1 回だけ（スナックバーは最新の 1 件しか出さないため。場所の削除と同じ）。
