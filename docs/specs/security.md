# データの扱いとプライバシーの仕様

位置情報を扱うアプリとして、**何を持ち、何を持たず、どこへ送るか**の約束。
実現方法は同名の設計書にある。

> 対応する要望: [../requirements.md](../requirements.md)（方針として大事にしたいこと／設定）。

---

## いま守れていること・いないこと

| 項目               | 現状                                                          |
| ------------------ | ------------------------------------------------------------- |
| データの置き場所   | 端末内。ただし**端末のバックアップで本人の Drive にも上がる** |
| データベース暗号化 | **していない**（平文）                                        |
| 自動削除           | **しない**（保持期間の概念を持たない）                        |
| アカウント・認証   | **無い**（ユーザーという概念そのものが無い）                  |
| 外部通信           | Google の地図タイルと、施設名の問い合わせだけ。HTTPS          |
| 端末バックアップ   | **有効**。下記「既知の穴」                                    |

クラウド同期（Phase 3）に入ると前提が変わるので、そのとき改めて決める。**本書は端末内の話に限る**。

## 収集するもの

**位置に関するものだけ**を持つ。デバイス固有 ID・連絡先・他アプリの情報・広告 ID は一切扱わない。

- GPS の座標と、端末が返す付随情報（精度・速度・provider など）を**取れるだけ全部**残す。
  記録時にしか取れない値なので、**精度を丸めたり間引いたりしない**。
- 施設名・住所・カテゴリは Google から取得して保存する。
- Google へ**送るのは座標だけ**。こちらの識別子は送らない。オフラインでは問い合わせないので、
  通信を切れば座標は外に出ない。

「施設名で振り返りたい」ために座標が Google に渡るのは避けられない。これはトレードオフとして受け入れている。

## 消し方

**いつ消すかは本人に委ねる。**アプリが勝手に消すことはない。

| 対象     | 導線                        | 備考                                                   |
| -------- | --------------------------- | ------------------------------------------------------ |
| 経路     | 履歴の一覧・詳細から        | 配下の点・立ち寄りも一緒に消える                       |
| 立ち寄り | 経路詳細から 1 件／まとめて | → [stops.md](stops.md)                                 |
| 場所     | 「場所」タブから            | 立ち寄り記録がある場所は消せない（記録を壊さないため） |

- いずれも**即時に消え**、スナックバーの「取り消す」でしばらくの間だけ戻せる。
- **「全データ削除」はアプリの中に用意していない**（端末のアプリ設定から消せるため）。

## 取る権限

**位置以外に個人情報へ触る権限は取らない**（連絡先・カメラ・ストレージなど）。

| 権限                       | 用途                                       |
| -------------------------- | ------------------------------------------ |
| 位置情報（正確・おおよそ） | GPS 記録                                   |
| バックグラウンドの位置情報 | 画面を離れても記録を続ける                 |
| フォアグラウンドサービス   | 記録中の常駐                               |
| 通知                       | 記録中であることの表示                     |
| ネットワーク               | 施設名の問い合わせとオンライン判定         |
| 電池の最適化の除外         | 記録が OS に止められないよう本人に依頼する |

- **起動しただけでは訊かない。**記録タブで権限が無いときにカードを出し、本人が押して初めて OS の
  ダイアログが出る。
- 「常に許可」は、前景の位置が許可された直後に続けて訊く。断られても前景では記録できる。
- 権限が無い／位置情報サービスが OFF のときは記録を開始せず、設定への導線を出す。

## 端末バックアップ

端末の自動バックアップが有効なので、**記録したデータごと本人の Google Drive に上がる**。
これは**そのまま許容すると決めている**（→ [ADR-0016](../adr/0016-allow-device-backup.md)）。

- 上がる先は本人の Google アカウントで、第三者には渡らない。
- 機種変更のときに、お出掛けの記録をそのまま引き継げる。
- 裏を返せば、**記録が Drive に平文で存在する**。Google アカウントが乗っ取られた場合の
  被害範囲に含まれる。

## やらないと決めていること

- **異常検知・アクセス監視** … 端末内で完結し、単一ユーザーなので守る相手がいない
- **セキュリティ監査ログ** … 同上
- **データの匿名化** … 共有機能が無いので匿名化する相手がいない

Phase 3（クラウド同期・複数人共有）に入ったら、いずれも前提が変わるので再検討する。
